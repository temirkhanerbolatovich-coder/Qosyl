# ADR-001: Единый корень Qosyl без изменения структуры приложения

Статус: выполнено по запросу владельца. Дата: 25.10.2026.

## Контекст

Рабочее приложение находилось в родителе, а Qosyl содержал вторую копию исследований и обзорный пакет. Это создавало два центра документации и случайный повтор зависимостей.

## Варианты

1. Перенести код в глубокую иерархию `10_Development/Source_Code` и изменить рабочие пути всех инструментов.
2. Сохранить стандартные технические каталоги в корне Qosyl, выделив номерные разделы для проектных материалов.

## Решение и причины

Выбран второй вариант: сохраняет npm, Docker, Prisma, тесты, START_DEMO и упаковочные скрипты. Исследовательский корпус переносится целиком, поскольку его скрипты и отчёты связаны относительными путями. Техническая документация остаётся в docs; единый индекс связывает её с продуктовыми разделами. Новые версии требований не придумываются.

## Последствия и риски

Рабочий каталог меняется на Qosyl. Git перенесён вместе с корнем; коммитов на момент переноса нет, существующий индекс и незавершённые изменения сохранены. `.env` и `.local` остаются приватными; их содержимое в отчёты не выводится. Исторические пути в реестрах сохраняются вместе с картой переноса. Только точные дубли с проверенной основной копией удалены.

При переносе PowerShell развернул junction внешнего research runtime: содержимое восстановлено на прежнее место, ссылка создана заново, 8528 файлов повторно сверены до очистки дубликата. Для последующих переносов в скрипте используется атомарное переименование каталога, сохраняющее junction. Перед перезапуском БД выполнена отдельная проверка холодного состояния.

## Дальнейшая работа

Указать новую папку Qosyl как рабочую в редакторе. Не запускать одноразовые миграционные скрипты повторно. Продолжать разработку только по отдельной задаче; эта реорганизация не меняет продуктовую логику.
