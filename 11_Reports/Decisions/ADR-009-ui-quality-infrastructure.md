# ADR-009 UI Quality на существующем стеке

Статус: принято для инфраструктуры; визуальные изменения отложены. Дата: 26.10.2026.

## Контекст

Пользователь запросил изучение UI/UX отчёта, постоянные инструкции, дизайн-систему и план, запретив менять UI и бизнес-логику на первом этапе. В Qosyl уже есть собственные CSS-компоненты, Tailwind, Lucide и Playwright.

## Рассмотренные варианты

1. Немедленно перейти на готовый UI kit и добавить все MCP/skills из отчёта.
2. Добавить только доказательно нужный dev-only accessibility инструмент и использовать существующую изоляцию E2E.
3. Ограничиться текстовым планом без исполняемой проверки.

## Решение и причины

Выбран второй вариант: @axe-core/playwright, отдельный профиль на четырёх ширинах, контрастный контракт документационных токенов, оригинальный repo skill с progressive disclosure. Существующий функциональный E2E остаётся отдельным. Все новые зависимости, источники и отложенные альтернативы описаны в [stack-decision](../../docs/stack-decision.md).

## Последствия и риски

Нет миграции продукта и конфликтующих UI-систем. Появился воспроизводимый baseline, однако в приложении остаются известные a11y issues; строгий gate корректно падает. Axe не заменяет keyboard, screen reader, usability, visual review и field performance. Отдельные изолированные E2E базы сохраняются для диагностики и со временем требуют осознанной очистки по точному имени.

## Следующая работа

После инфраструктурного этапа исправить подтверждённые UI-001/UI-002 в отдельно заданном объёме, затем внедрить один эталонный каталог. Новые widgets/Storybook/MCP оценивать по необходимости, не из-за их присутствия в исходном отчёте.
