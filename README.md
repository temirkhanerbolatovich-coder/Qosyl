# Qosyl

**Размещённый сайт:** [qosyl.duckdns.org](https://qosyl.duckdns.org). Настройка DNS и ограничения — в [инструкции Oracle Cloud](docs/deployment/oracle-duckdns.md). Состояние исходников в этой ветке может отличаться от работающей версии сайта.

[Дизайн-система Qosyl 1.0](docs/design-system.md): Deep Blue/Teal, локальные Inter/Manrope, светлая/тёмная/системная темы и исходный логотип. [Отчёт внедрения и проверки](docs/qa/design-system-implementation.md), [постоянная база UI Quality](docs/ui-quality/README.md).

Общий поиск возможностей (26.10.2026): локальные HTML/RSS-источники, категории грантов/стипендий/стажировок, поиск и направления в admin и `/opportunities`. Собрано 109 реальных материалов из семи источников в закрытую очередь; автоматического одобрения нет. [Запуск, проверки и границы](docs/opportunity-discovery.md).

Qosyl помогает студентам получить первый оплачиваемый проектный опыт, а предпринимателям и организациям — найти исполнителя для небольшой задачи с понятным результатом. Завершённые проекты могут стать подтверждёнными работами в портфолио.

Основной сценарий: задание и бюджет → модерация → отклики → выбор исполнителя → согласование условий → сдача и приёмка → раздельный учёт заявлений об оплате → портфолио с согласиями. Платежи проходят вне платформы; гарантий оплаты и хранения денег нет. Цель — первый профессиональный опыт, а не универсальная биржа или социальная сеть.

Локальный MVP на Next.js, TypeScript, PostgreSQL и Prisma включает роли, модерацию, основной процесс проекта, отзывы, портфолио, два шаблона задач, аналитику Q10 и фоновую актуальность Q11. API разделено на серверные модули и имеет общий OpenAPI-контракт. Миграции расширяют существующую БД; прежние пользовательские данные сохраняются.

В admin → «Сбор возможностей» находятся источники, очередь, редактор и журнал импорта. Одобренные карточки появляются на главной под CTA и скрываются при изменении/отзыве/expiry/выключении. В admin → «Лиды и обсуждения» ведётся отдельный приватный реестр. После записи ручного согласия конкретный заказчик сам заполняет бюджет и критерии и создаёт обычный черновик с модерацией. Автоматических заказов, комментариев и внешних сообщений нет. Следующие решения — реальный пилот и конкретный разрешённый социальный адаптер. Публичная эксплуатационная готовность, реальные оплаты, контакты, партнёрства и спрос бизнеса этой реализацией не подтверждаются.

Последний предоставленный опрос содержит **45 ответов**: интерес 4–5 у 41/45, гарантия оплаты важна 35/45, чёткое ТЗ — 28/45. Это смешанная нерепрезентативная выборка. Исторические срезы 27 и 42 сохранены отдельно по происхождению; их нельзя складывать или выдавать за актуальные 45.

## Запуск и проверки

Рабочий каталог для всех команд — **эта папка Qosyl**, а не её родитель. Требуются Node.js и PostgreSQL по [руководству](docs/development-guide.md). На подготовленном компьютере открыть [START_DEMO.cmd](START_DEMO.cmd) или выполнить `npm run demo`. Существующие `.env` и `.local` перенесены и сохранены. Для нового окружения: `npm ci`, `npm run setup`, `npm run dev`.

Проверки: `npm test`, `npm run lint`, `npm run typecheck`, `npm run build`. E2E: `npm run test:e2e` использует отдельную тестовую БД. Дополнительно: `npm run test:db` проверяет ограничения PostgreSQL на подготовленной E2E-базе, `npm run api:check` сверяет OpenAPI с валидаторами. Последняя проверка API/БД — [отчёт](docs/qa/api-database-boundaries.md); отчёт реорганизации сохраняет отдельный исторический срез.

## Статус требований и решений

Владелец задал название Qosyl, концепцию первого оплачиваемого опыта, необходимость дополнительного модуля и консолидацию проекта. ТЗ v2 сохраняется как исходная спецификация существующего MVP; единый перечень показывает расхождения и предложения, а не выдуманное формальное утверждение каждой строки. RSS + ручной ввод реализованы для внутренней проверки. Реальные источники пилота, порядок социальных адаптеров, монетизация, операционные роли и параметры пилота требуют решений соответствующего этапа.

Исходный аудит в `11_Reports/Audit_Reports/initial-audit` описывает состояние до реализации; текущий статус нужно читать в `progress.md` и QA. Архивный README больше не определяет расположение кода. Исходные реестры исследований сохранены с историческими путями; таблица переноса позволяет восстановить их происхождение.

Сырые ответы, контакты, локальная почта, `.env`, резервные копии и архивы предназначены для внутренней работы. Они исключены из Git и Docker-контекста; это не шифрование. Не публикуйте целиком папку проекта. Внешние источники исследования при реорганизации заново не проверялись.

`npm start` запускает web, worker актуальности и worker контента под общим supervisor. Контентный worker не обращается к внешним источникам при выключенном сборе; архивирование истёкших публикаций и фильтр сроков независимы от сбора. Инструкции: [сбор](docs/content-intake.md), [модерация и лента](docs/content-moderation.md). Проверка — `npm run test:content` на подготовленной E2E-БД.
