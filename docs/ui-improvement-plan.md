## Направление и порядок

Выбрана «Рабочая биржа»: сохранить узнаваемый акцент, увеличить полезность условий проекта и уменьшить отвлекающий chrome. Эталонный экран — `/projects`: он одновременно проверяет типографику, сетку, ProjectCard, фильтры, query, пустую выдачу и мобильное поведение. Главная не должна определять дизайн кабинета или навязывать маркетинговую композицию рабочей области.

## Как устранять шаблонность

У каждого элемента задать вопрос: помогает ли он выбрать/сдать задачу или принять решение? Декоративный eyebrow без новой информации убрать, а метку ДЕМО сохранить. Результат работы показывать конкретно; не заменять его общими обещаниями «раскрой потенциал». Карточки использовать для сравнения проектов, списки/строки — для операций; не упаковывать каждый абзац в одинаковый контейнер. Нулевые счётчики не выдуманы, но в пустом кабинете следующий полезный шаг может быть важнее их площади. Это требует проверки, не безусловного удаления.

Не вводить dark mode, нестандартный шрифт, motion library, command palette или графики ради ощущения современности. Отсутствие иллюстраций сейчас не дефект: продукт опирается на задачи и доверие. Разрешённый будущий визуальный эксперимент должен иметь цель, доступные права на ассеты и измеримый критерий принятия.

## Контроль изменений

Внедрять последовательными небольшими diff, не смешивать CSS-перестройку с API/схемой/ролями. Сохранять screenshot до/после и наблюдаемые регрессии. Сначала исправить реальную доступность, затем типографику/плотность. Не сбрасывать пользовательскую БД и не публиковать pending материалы для красивого демо. Новый пакет добавлять только при подтверждённом пробеле existing stack; не использовать `--force` для обхода peer-конфликта.

Оценки трудозатрат пока не назначены: нет проверки всех ролей и пользовательского исследования. Следующее конкретное действие после завершения инфраструктурного этапа — отдельное внедрение UI-001/UI-002, затем эталонного каталога, в объёме следующей задачи пользователя.
