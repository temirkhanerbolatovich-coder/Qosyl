Актуальный машиночитаемый контракт — [OpenAPI 3.1](api/openapi.json), генерируемый из действующих валидаторов. `npm run api:generate` обновляет его; `npm run api:check` проверяет отсутствие расхождений. Устройство серверных модулей описано в [архитектуре](architecture.md), связи и ограничения — в [документации БД](database.md).

Существующие `/api/platform` и `/api/profile` сохраняют URL, параметры и `{data}` при успехе. Ошибка содержит прежнее текстовое поле `error` и добавленный стабильный `code`; для ошибок профиля возможно `fields`. Коды: `VALIDATION_ERROR`, `UNAUTHENTICATED`, `FORBIDDEN`, `NOT_FOUND`, `CONFLICT`, `PAYLOAD_TOO_LARGE`, `UNSUPPORTED_MEDIA_TYPE`, `RATE_LIMITED`, `INTERNAL_ERROR`, `SERVICE_UNAVAILABLE`. Все ответы этих двух маршрутов имеют `Cache-Control: private, no-store`; `/api/health` и Better Auth используют свои форматы.

Предел тела `/api/platform` — 65 536 байт, `/api/profile` — 16 384 байта, `/api/admin/content` — 32 768 байт. Проверяется сам поток, а не только Content-Length. Тип тела должен быть `application/json` (регистр не важен, charset разрешён); похожие строки вида `application/json-invalid` отклоняются с 415.

Каталог проверяет целые `page=1..10000`, бюджет `0..10000000`, трудоёмкость `0..160`, известные category/mode/difficulty/sort, длины поиска и существующую календарную дату. Пустые поля формы игнорируются; неизвестный view, дробная страница, невозможная дата и обратный диапазон бюджета дают 400. Календарный `dueBefore` означает конец дня UTC+05; ISO datetime требует часовой пояс. Сортировка новых заказов имеет стабильный вторичный ключ ID. До этого часть некорректных значений могла доходить до Prisma или молча игнорироваться.

Административная очередь исключает `contactPrivate` и `locationPrivate` каждого проекта. Роль admin не открывает чужую рабочую область; чтение собственного профиля не возвращает записи Account, Session или токены. Исходные подробности действующего контракта сохранены ниже.

## Подробности операций

Административное чтение Qosyl: `GET /api/platform?view=pilotMetrics`, только admin. Контракт, знаменатели и ограничения: [Результаты пилота](pilot-metrics.md). Просмотры ограничены авторизованными студентами и началом сбора; это не полная посещаемость всех гостей.

Локальный адрес по умолчанию: `http://localhost:3000`. API использует ту же cookie-сессию, что интерфейс. Секреты, cookie и персональные данные не помещаются в примеры или Git.

## Общие правила

`GET /api/platform?view=...` возвращает `{ "data": ... }`. `POST /api/platform` принимает JSON с полем `action` и параметрами операции. Ответ успешного изменения — `{ "data": { "ok": true } }`, а создание может вернуть созданную сущность. Ошибка — `{ "error": "Человеческое объяснение" }` и соответствующий HTTP-статус.

Изменения требуют авторизованной активной сессии, корректного `Origin`, серверной роли и права на конкретную сущность. Проверка выполняется сервером по актуальной записи, переданный клиентом userId/role не дает полномочий. Клиент должен обрабатывать ошибки проверки данных, доступа, состояния, конфликт и rate-limit. После изменения перечитывается актуальная проекция. Не повторяйте финансовые или статусные действия слепо после потери ответа.

## Поля заказа

Обновление25.10.2026 после приемки: `acknowledgePayment` со статусом `disputed` атомарно создает обращение модератору и уведомляет другую сторону. Ответ по обращению сам не меняет платежное заявление. `pauseProject` администратора уведомляет автора с причиной. `cancelProject` закрывает активные отклики как `not_selected`, уведомляя исполнителей.

Операционный `GET /api/health` проверяет доступ к БД и возвращает только `{status:"ok"}`/200 или `{status:"unavailable"}`/503 с `Cache-Control:no-store`; ошибки и реквизиты не раскрываются. В закрытом развёртывании внешний доступ ограничен входом пилота на proxy.

`title`, `category`, `problem`, `description`, `deliverables`, `acceptanceCriteria: string[]`, `skills: string[]`, `difficulty: beginner_friendly | intermediate`, `mode: remote | onsite | hybrid`, `city`, `locationPrivate`, `contactPrivate`, `budgetKzt: positive integer`, `estimatedHours: positive integer`, `dueAt: ISO datetime`, `preferredTime`.

Расчет фиксированный, в ₸. Точная локация и способ контакта не включаются в публичную проекцию. Цена, результат и критерии обязательны. Публикация не подтверждает оплату и не запускает платеж.

## Аутентификация и профиль

Better Auth обслуживает `/api/auth/*`. Основные операции:

- `POST /api/auth/sign-up/email`: `{name,email,password,adultConfirmed:true,privacyConsent:true}`. Пароль 12–128 символов. Отсутствие обязательных согласий отклоняется сервером; административная роль не принимается из формы.
- `POST /api/auth/sign-in/email`: `{email,password}`.
- `POST /api/auth/sign-out`: завершение своей сессии.
- `POST /api/auth/request-password-reset`: `{email,redirectTo:"http://localhost:3000/auth/reset-password"}`; ответ не должен раскрывать наличие email.
- `POST /api/auth/reset-password`: `{token,newPassword}`; токен ограничен временем и одноразовый, прежние сессии отзываются.
- `GET /api/auth/get-session`: текущая сессия; защищенные операции дополнительно проверяют status пользователя в базе.

`GET /api/profile` возвращает безопасную текущую идентичность, профили и внешние работы. `POST /api/profile` принимает `role: student|client`, `name`, `city` и поля профиля. Student: `bio`, `institution`, `discipline`, `weeklyHours`, `skills`, `formats`, `isPublic`, `externalWorks:[{title,description,url}]`. Client: `organisationName`, `industry`, `contact`, `description`. Добавление второй рабочей роли не дает admin. Проверенный статус заказчика нельзя установить этим endpoint.

В локальном режиме письма находятся только в игнорируемом `.local/mail/` и читаются командой `npm run mail`. HTTP-endpoint для чтения писем отсутствует. Публичный production без настроенной почты и подтверждения email запрещен.
