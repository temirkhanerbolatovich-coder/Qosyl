## Что устанавливает E2E

1. Гость не видит черновик, приватные контакты и точную локацию.
2. Заказ проходит отклонение с причиной и одобрение; серверные фильтры действительно меняют выдачу.
3. Самоотклик, повторный активный отклик, чужое редактирование, чужие заявки, преждевременная приемка и повторное назначение запрещены.
4. Сначала одно согласие оставляет assigned; второе переводит в работу. Старая версия сохраняется, устаревшее подтверждение отклоняется.
5. Новые адреса в еще не согласованных версиях и сводке исполнителя скрыты. Сдача после двух согласий, правки по критериям, повторная сдача, приемка работают.
6. Accepted/completed и оплата независимы. Оба закрытия обязательны; сообщение заказчика не означает получение студентом.
7. Публичное портфолио требует обоих согласий; изменение содержимого сбрасывает их, устаревший timestamp не подтверждает новую версию. Приватные ссылки сдачи не публикуются автоматически.
8. Отзывы принадлежат участникам, повторные/ранние отзывы запрещены. Блокировка лишает доступа действующую сессию. PostgreSQL отвергает подмену событий, сдач и удаление отзывов.
9. Через настоящий390px-интерфейс выполнены отклик → выбор → оба согласия → сдача → конкретные правки → повторная сдача → приемка. Проверена регистрация и страницы с горизонтальным overflow≤1px на390/768/1440.
10. Отсутствие соединения и настоящий20-секундный таймаут показывают понятные ошибки. Неверные JSON, oversized payload и чужой Origin отвергаются. Oxford Team явно ДЕМО, отклики выключены.
11. Через реальный desktop-интерфейс заказчик заполнил и сохранил черновик, отправил на модерацию; модератор одобрил. Автор приостановил, увидел возможность повторного редактирования, затем отменил объявление. Серверные статусы проверены независимо от сообщений интерфейса.

## Исправления, найденные проверками

- Утечка точного адреса через dashboard до согласования устранена; добавлена проверка.
- Новая версия условий ранее могла раскрывать адрес на основании старого согласия. Теперь каждый снимок проверяется отдельно.
- Согласие привязано к конкретному agreementId/updatedAt; скрытые поля заказчика не стираются предложением исполнителя.
- Чек-листы привязаны к версии условий; аудит и сдачи защищены триггерами.
- Уточнены мобильные стили полей/ошибок, подписи, контраст заголовков, доступность действий по состоянию. Пауза позволяет снова редактировать и отправлять заказ.
- Устранено дублирование сообщения результата действия заказчика: две одинаковые live-region мешали чтению и строгой проверке интерфейса. Теперь сообщение показывается в области действия.
- Начальные тестовые селекторы конфликтовали с Next route-announcer, meta description и полным именем вложенного select. Ожидание навигации не должно принимать `/client/projects/new` за созданный `/projects/[id]`. Тесты уточнены; итоговый полный прогон повторен без пропуска проверок и без ослабления продуктовых ограничений.

## Ограничения и непроверенное

- SMTP и реальная доставка verification-писем не настроены/не проверены. Восстановление проверено через закрытый локальный почтовый ящик. Публичный запуск без почты запрещен.
- Реальные Safari iOS/Firefox, внешние API/платежи, публичный хостинг, нагрузка, внешний pentest, восстановление резервной копии не проверялись.
- Нет бинарных загрузок, AI, банковских операций, escrow, гарантии оплаты. P0 принимает HTTPS-ссылки; закрытое файловое хранилище — P1.
- Автоматическое истечение/напоминания — P1. Уже просроченные заказы исключаются сервером из каталога без удаления данных.
- Next.js streaming у закрытого `/talent/[id]` может вернуть HTTP200 с безопасным экраном notFound (soft404). Приватные данные не передаются; защищенный API возвращает401/403/404 по контракту.
- CSP допускает inline для Next hydration; nonce-based CSP требует отдельной регрессии. ESLint9 выбран по совместимости плагинов, его обновление остается долгом инструментария.
- Проверка WCAG2.2AA целевая: подписи/клавиатура/focus/адаптивность проверены в объеме smoke. Формальной сертификации доступности и юридической проверки нет.

**Статус:** функциональный локальный MVP с настоящей БД и проверенным сквозным сценарием. Не заявление production-ready; публичный пилот требует эксплуатационной и правовой подготовки по `product-backlog.md`.
