# Результаты пилота Qosyl

Обновление 26.10.2026. Административная вкладка «Результаты пилота»: историческая воронка проектов, измеренные просмотры, 30-дневные повторы и отдельный журнал затрат. Для гостя — 401, для обычного пользователя — 403 при чтении административных данных.

## Определения

Когорта воронки — проекты с известным moderateProject/approve=true без demo-проекта, demo-заказчика и назначенного demo-исполнителя. Отмены сохраняются. Один проект считается один раз на этапе. shareOfPublished=count/published; при нулевом знаменателе null. Это доля проектов от опубликованных, а не конверсия соседних действий конкретного человека. paid — текущий accepted/completed с двумя датами оплаты и confirmed_received_by_student; споры исключены. firstPaidStudents — уникальные исполнители этих проектов. repeatClients сохраняет прежний счёт повторов за всю историю.

Просмотр — опубликованная страница в активной вкладке минимум одну секунду у авторизованного студента. Только POST recordProjectView пишет ProjectView; GET и prefetch остаются чтением. Автор, admin, demo-аккаунты/проекты/заказчики исключены. Сервер берёт studentId из сессии. Составной ключ projectId/studentId сохраняет только первую дату; повтор и перезагрузка не увеличивают число. Новые IP, cookies, fingerprint и гостевые идентификаторы не собираются.

engagement.startedAt — сохранённое начало нового сбора. viewedPairs — уникальные измеренные пары; appliedPairs — пары с откликом не раньше просмотра; conversionRate=appliedPairs/viewedPairs либо null. Отозванный отклик остаётся фактом. Для повторного отклика учитывается applyToProject из истории с тем же actorId: createdAt строки отклика не меняется при повторе. Исторические отклики без соответствующего измеренного просмотра не входят в эту конверсию. viewedProjects — сколько разных проектов имели такие просмотры.

views теперь number|null: null означает отсутствие инициализированного сбора, 0 — сбор включён, но подходящих просмотров пока нет. Это уточнение прежнего внутреннего API, где views всегда был null; текущие OpenAPI, UI и тесты обновлены вместе. coverage явно равен tracked_authenticated_students. Полная посещаемость гостей неизвестна.

repeat30Days использует max(первая приёмка, clientPaidAt, studentReceivedAt) для первого квалифицированного результата заказчика. Только после окончания 30 суток окно mature и входит в знаменатель. Повтор — другой оплаченный и принятый проект не позже конца этого окна. Незавершённые окна показаны отдельно; repeatRate=null при отсутствии mature. Месячная когорта относится к первой дате по UTC+05. Отсутствующая история приёмки делает начало окна ненадёжным; такой клиент попадает в undatedClients и исключается из расчёта окон. asOf фиксирует момент среза.

Оплата — заявления участников, не банковская сверка. Текущий спор или изменение состояния может пересчитать показатели. Исторические времена, записанные до настройки UTC, не сдвигаются автоматически и требуют проверки перед точными временными выводами.

## API

- GET /api/platform?view=pilotMetrics — admin, формулы выше, без идентификаторов просмотревших студентов.
- POST /api/platform action=recordProjectView, projectId — активный student с обычными проверками origin/email/размера/лимита. Подходящая повторная запись безопасна; недоступный проект даёт 404, demo/owner/admin inspection не считают.
- GET /api/platform?view=pilotCosts&page=1 — admin, 25 записей на страницу, page до 10000, hasMore. Итоги всей активной истории, не только страницы.
- POST action=recordPilotCost: idempotencyKey UUID, kind=acquisition/moderation/support/operations, occurredAt ISO, minutes=0..100000, amountKzt=0..10000000, description=3..1000, projectId необязателен. Минимум время или сумма положительны. Дата не позже текущего времени более чем на 5 минут. Связанный проект должен быть реальным.
- POST action=voidPilotCost: costId и reason=10..1000. Исходные поля сохраняются. Отмена с теми же автором/причиной повторяема; другой повтор даёт 409.

Для повторной записи расхода использовать тот же ключ и поля; изменённый payload с этим ключом даёт 409. В UI ключ сохраняется после неизвестного исхода. Перед кнопкой «Новая запись» сначала обновить журнал и проверить, не сохранился ли прежний расход. Смена ключа означает намерение создать новый расход.

Время команды и деньги показываются отдельно. Ставка часа, комиссия, выручка, прибыль и CAC автоматически не предполагаются. В описание нельзя включать контакты, реквизиты или лишние персональные сведения. Ошибку исправляют отменой и новой записью; удаление и редактирование исходного расхода запрещены также в БД.

## Запуск и проверки

Миграции: 20261026100000_pilot_analytics и 20261026103000_utc_pilot_timestamps. Pool приложения использует UTC; новые таблицы имеют явные UTC-defaults независимо от локальной настройки PostgreSQL. Вторая миграция переинициализирует только пустую новую коллекцию; при данных и будущем начале останавливается. Не меняйте её начало вручную.

Сначала node scripts/test-db.mjs, npm run test:db и полный build/E2E на отдельной базе; перед основной — npm run db:backup -- --verify. Применение и восстановление проверены, результаты в [QA](qa/q10-pilot-analytics.md). Контракт: [OpenAPI](api/README.md), архитектурное решение: [ADR-003](../11_Reports/Decisions/ADR-003-pilot-measurement.md).

Для малого пилота минимальная история считается в памяти без молчаливого ограничения выборки. Перед большим объёмом необходимы SQL-агрегации и EXPLAIN ANALYZE. Отправка просмотра зависит от браузера и сети, не тормозит основной процесс; reopen повторит запрос безопасно. Наличие нескольких аккаунтов не исключено. Сырые пары просмотров не предоставляются публичным API.
