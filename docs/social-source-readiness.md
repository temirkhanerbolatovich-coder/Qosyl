## Выбор

| Вариант | Установлено | Требуется |
| --- | --- | --- |
| Telegram Bot API | Получает посты каналов, участником которых является бот; это не поиск по всему Telegram | Конкретный канал, возможность добавить отдельного бота, ID канала, ответственный admin Qosyl и локальный токен |
| Threads | В официальной коллекции Meta найден keyword_search | Проверить актуальный контракт, permissions, охват, квоты и условия; подтвердить доступ приложения |
| Другой источник | Требования не определены | Название, источник и разрешённый способ получения данных |

Telegram — рекомендуемый первый вариант, **если владелец канала может добавить бота**. Для чужих каналов без этого доступа он задачу не решает. Платформа пользователем ещё не выбрана. Наличие credentials, права на использование данных и реальные лиды не подтверждены. Стоимость и числовые квоты не выдумываются.

## Проверенные ограничения Telegram

Источники: официальные [Bot API](https://core.telegram.org/bots/api#getting-updates), [getUpdates](https://core.telegram.org/bots/api#getupdates), [FAQ](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get).

- Очередь хранится не дольше 24 часов. Выключенный локальный компьютер может пропустить обновления; непрерывный мониторинг не обещается.
- getUpdates и webhook взаимоисключающие. Чужой webhook требует остановки с понятной ошибкой; автоматически удалять его или сбрасывать очередь нельзя.
- Запрос с новым offset подтверждает предыдущие обновления. Использовать его можно только после сохранения обработанной порции в БД.
- update_id помогает исключать повторы; после долгого отсутствия обновлений следующее значение может быть случайным. Разрыв ID не означает известное количество пропущенных постов.
- getUpdates принимает limit 1–100. allowed_updates не исключает старые уже накопленные события; локальная проверка типа и разрешённого chat.id обязательна.
- Токен находится в URL API. Полный URL и исходные исключения HTTP-клиента не должны попадать в журнал или браузер.

Orbit search/integrate выполнены для getUpdates. Ограничение fit — отсутствие удаления webhook в выбранном запросе; приложение и не должно самостоятельно менять конфигурацию чужого бота. Пример URL Orbit не копируется в код: первичный контракт — Telegram.

Для Threads обнаружена [официальная коллекция Meta](https://www.postman.com/meta/threads/request/34203612-b3b2c12a-7ce6-4d86-a3c6-6d31e3b66ea1), но её страница отдаёт оболочку входа. Meta Developers вернул 429/ошибку чтения. Поэтому актуальные поля, permissions, лимиты и публичный охват пока не считаются проверенными; сторонние скрейперы не используются как контракт.

## Шаги после выбора источника

1. Зафиксировать платформу, один источник, ответственного и доступ. Не использовать аккаунты/ботов другого проекта без решения владельца.
2. Описать узкий контракт провайдера: вход, нормализованный кандидат, идентичность, редакции, ошибки. Публичные возможности и приватные лиды остаются разными потоками; тип кандидата подтверждает оператор.
3. Добавить отключённый по умолчанию адаптер в существующий монолит. Настройки/аудит доступны admin; токен — только на сервере, без передачи через UI и примеры OpenAPI.
4. Реализовать ограниченный worker, единственного потребителя, устойчивую дедупликацию и атомарное сохранение порции/курсора. Идентичность сообщения включает аккаунт/канал/ID сообщения, а не только update_id.
5. Сохранять изменения отдельно: не перезаписывать проверенное описание, согласие или Project. Повтор не возрождает отказ/архив. Поведение edits зафиксировать в контракте до реализации.
6. Обработать 401/403, webhook/второй consumer 409, 429 с retry_after, timeout, 5xx, неверный JSON и размер ответа. Ошибки доступа требуют оператора; повторы временных ошибок ограничены.
7. Проверять выключатель до внешнего запроса и перед сохранением; определить судьбу уже начатого запроса. Повторное включение не восстанавливает утраченную очередь.
8. Прогнать настоящий HTTP-клиент против локального сервера-имитатора, затем проверки БД/UI. Реальный доступ проверить отдельно на выбранном источнике.

Адаптер не отправляет людям сообщения, не публикует ответы и не создаёт Project. Сохраняется путь «проверка → ручной контакт → согласие → действие заказчика → модерация».

Биржа должна работать при отказе источника.
