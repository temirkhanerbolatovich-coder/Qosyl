# Общий поиск возможностей: сайты и RSS

Локальная первая версия 26.10.2026. Сбор и поиск расширяют существующий модуль Content intake; marketplace Project/Lead не создаются.

## Пользовательский путь

В верхнем меню доступна страница /opportunities. Поиск по тексту, типу, направлению и явно записанной географии работает по одобренным актуальным редакциям включённых источников. По шесть карточек на страницу. Неодобренные материалы студентам не видны.

Администратор → «Сбор возможностей» → форма поиска над материалами. Она ищет по всей базе последних редакций, с прежними статусами и пагинацией по 20. Найденный материал нужно проверить в оригинале, при необходимости отредактировать, указать срок актуальности и одобрить прежним редакционным действием. Изменение исходника снова закрывает материал на проверку.

## Источники

Теперь type=html использует feedUrl как адрес HTML-страницы. Типы manual и rss сохраняются. Точная привязка к allowedHost, HTTPS, DNS pinning, запрет частных IP, проверка каждого redirect, лимиты 1 MiB / 10 секунд и MIME-проверка сохранены. HTML допускается только в явном режиме html; RSS не начинает принимать HTML-ошибки.

Cheerio разбирает разметку без браузера и выполнения скриптов. Поддерживаются карточки article, заголовки со ссылками, содержательные ссылки внутри указанного раздела, опубликованные статьи с явной семантикой article. Для Astana Hub отдельно извлекается только буквальный URL из Alpine @click; выражение никогда не выполняется. Внешние ссылки отбрасываются. Одинаковые URL сворачиваются. Неизвестная структура/JS-shell становится ошибкой источника, а не успешной пустой выдачей.

Новые категории: grant, scholarship, training, news, article; прежние категории сохранены. Классификация эвристическая и редактируется человеком. Направления определяются поисковыми словами, не являются оценкой права участия. Неизвестная специальность не исключает материал из общего поиска. Известные даты сохраняются; даты без timezone и текстовые дедлайны не выдумываются. Регион не выводится из имени автора.

## Запуск

После резервной копии: npm run db:migrate. Это расширение CHECK-ограничений; прежние записи не удаляются. npm run opportunities:collect включает модуль и семь заданных публичных источников в локальной БД, запускает существующий worker и сохраняет отчёт outputs/opportunities/live-collection.json. Скрипт проверяет LOCAL_DEV_MODE/DEMO_ENABLED, loopback и имя локальной БД. Он использует существующего demo-admin и штатную аудитируемую команду создания источника.

Повторный запуск переиспользует источники и соблюдает расписание (шесть часов), не сбрасывает nextRunAt для лишнего запроса. Фоновый content-worker под npm start продолжает сбор. Выключение модуля и источника, блокировки, квоты, backoff и история прежние. Автоматического одобрения нет.

## Реальный сбор

- Astana Hub /ru/event/: 45 карточек, включая Semey Hub и Pavlodar Hub.
- science-fund.kz/feed/: 10 RSS-записей, включая грантовое финансирование.
- bolashak.gov.kz/ru/: 4 материала, включая научные стажировки.
- amu.edu.kz/ru/infocenter/news/: 7 материалов медицинского университета.

- www.kaznaru.edu.kz/ru/anons: 30 объявлений, включая обучение в Южной Корее и научные гранты.
- abai.university/ru/news: 5 первоначально собранных материалов; исправленный парсер также поддерживает карточки cnews__title без заголовочного HTML-тега.
- iuth.edu.kz/ru/: 8 материалов университета туризма, включая академическую мобильность.

Всего 109 материалов, все в pending_review. Это не 109 подтверждённых действующих конкурсов: есть новости, итоги, кадровые объявления и материалы с неизвестным сроком. Реальный поиск по направлениям: IT — 36, инженерия — 18, бизнес — 15, педагогика — 10, медицина — 4, гуманитарные — 8, сельское хозяйство — 7, туризм/сервис — 5; наборы пересекаются и могут включать нерелевантные совпадения. Исходные URL и примеры находятся в live-отчёте.

Read-only проверка новых источников: node --conditions=react-server --import tsx scripts/probe-opportunity-sources.ts. Она использует тот же ограниченный HTTPS transport и parser, сохраняет outputs/opportunities/source-probes.json, не меняет базу. Главная страница KazNAI возвращает также навигационные карточки; как источник она не включена. Для разовой коррекции 33 существующих карточек KazNARU/Abai использована штатная editContent с optimistic concurrency, редакциями и аудитом; публикаций и новых материалов при исправлении не создано. Отчёт metadata-repair.json. Последующие обновления идут по прежнему расписанию.

## Контракт

GET /api/content/posts сохраняет envelope data.posts и limit 1–6; добавлены page 1–10000, q до 100 символов, category, specialty, geography до 120. GET /api/admin/content использует те же фильтры поверх последней редакции, сохраняя status, page, total и остальные поля. Все параметры валидируются сервером. q — буквальная подстрока, не SQL/regexp. Кириллица RU/KZ нормализуется независимо от C-локали PostgreSQL. Секреты, аудит, права и история не входят в публичную выдачу. OpenAPI обновлён.

## Проверки и ограничения

303 unit, 30 интеграционных сценариев (включая реальный TLS transport для HTML, SSRF, worker, поиск последней редакции, SQL-подобный запрос, скрытие pending/изменённого материала), lint, TypeScript/build и api:check. Контентные тесты создают отдельную локальную БД с уникальным суффиксом; при успехе удаляют только её, при ошибке сохраняют. Старая тестовая база со 100 источниками оставлена без очистки.

Postman CLI отсутствует: нативная TLS-fixture не называется Postman simulation. Полный браузерный E2E-прогон и текущие HTTP-проверки описаны в QA-отчёте docs/qa/opportunity-discovery.md.

Gov.kz отдаёт JS-shell, Youth.kz превышает действующий лимит тела, некоторые сайты вузов отвечали 500/timeout. Они не включены как якобы работающие источники. Региональные хабы покрыты только карточками центрального портала, не всеми их сайтами/соцсетями. Telegram/Instagram/Threads браузерные адаптеры не входят в этот этап. Условия использования и право перепубликации проверяет редактор; публичный доступ не объявлен автоматическим разрешением копирования.

E2E UI по умолчанию создаёт отдельную БД student_marketplace_e2e_ui_<суффикс>, история которой сохраняется для диагностики. E2E_DATABASE_NAME позволяет явно выбрать только валидное изолированное имя; основная база отклоняется. Интеграционные контентные тесты удаляют свою временную БД только после успешного завершения.

Тестовое окружение E2E принудительно устанавливает THREADS_SEARCH_ENABLED=false и пустой THREADS_ACCESS_TOKEN; действующий токен владельца не наследуется тестовым сервером. Новые UI-сценарии проверяют поиск RU в верхнем регистре, категорию в закрытой очереди и публичный поиск одобренной карточки.
