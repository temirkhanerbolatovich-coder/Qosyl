# Приёмка UI

Для каждого пункта фиксировать passed / issue / not-tested с доказательством. Непроверенный пункт не становится passed из-за успешной сборки.

## До изменения

- [ ] Заданы пользователь, цель, маршрут, роль и разрешённый объём изменений.
- [ ] Изучены существующие компоненты/тесты и выбрано визуальное направление.
- [ ] Описаны сохраняемые API, query, auth, ограничения пилота, moderation и consent.
- [ ] Для новой зависимости подтверждены источник, лицензия, engines/peers и конкретная необходимость.

## Экран и поведение

- [ ] Основная задача/следующее действие понятны; нет фиктивных KPI, партнёрств и верификации.
- [ ] Поля результата/бюджета/часов/срока/формата читаются и сравниваются.
- [ ] ДЕМО, неизвестные даты и происхождение возможностей обозначены честно.
- [ ] Loading, empty, error, focus, hover, pending/disabled и success проверены там, где применимы.
- [ ] Поиск, filters, pagination и возврат сохраняют ожидаемое состояние.
- [ ] Сценарии student/client/admin, затронутые изменением, проверены в настоящем изолированном приложении.

## Доступность и responsive

- [ ] Light/Dark на 320/375/390/768/1024/1440/1920 и затронутые границы breakpoint: ключевые screenshots прочитаны визуально, прочие явно обозначены как автоматические проверки.
- [ ] Нет page overflow, перекрытий, клиппинга и слишком узких карточек; длинные RU/KZ тексты проверены.
- [ ] Tab/Shift+Tab/Enter/Space/Escape, skip link, возврат focus и видимость focus проверены в нужных widgets.
- [ ] Labels, accessible name, headings/landmarks, link/button и сообщения ошибок осмысленны.
- [ ] Axe serious/critical отсутствуют в покрытых состояниях; moderate/minor и incomplete рассмотрены, а не скрыты.
- [ ] Контраст токенов и фактических rendered controls проверен; нет смысла только в цвете.
- [ ] Zoom 200%, reflow 320 CSS px, reduced motion и touch target проверены отдельно; screen reader — отдельный статус.

## Технический gate

```powershell
npm run ui:tokens
npm run test:ui:baseline
npm run test:ui
npm run lint
npm run typecheck
```

Для изменения production-кода также релевантные unit/integration/E2E и build. У UI runner baseline-режим сознательно не блокирует известные a11y/overflow issues; он не предназначен для скрытого отключения gate перед релизом. Не обновлять screenshots автоматически в качестве «исправления».

- [ ] Console/page errors, failed requests и неожиданная навигация проверены.
- [ ] Performance измерено подходящим способом либо явно not-tested, без подмены p75 лабораторным замером.
- [ ] Diff не содержит посторонних изменений и секретов; docs/план отражают фактический результат.
- [ ] Итог содержит реальные команды, результаты, пути артефактов и оставшиеся ограничения.
