# Стартовое задание для Codex

Готовый текст, который владелец вставляет в Codex. Документация для исполнителя — в этом каталоге, точка входа — [README.md](README.md).

## Перед запуском (проверяет владелец)

1. Codex работает от ветки **`main`** — 15.11.2026 в неё влита `feature/opportunities-local` вместе с этой документацией.
2. Секреты не передаются: `.env`, `.local/`, пароли демо-аккаунтов остаются только на компьютере владельца. Для тестов в облаке Codex использует временную PostgreSQL, как в CI ([docs/testing/ci.md](../testing/ci.md)).
3. Если Codex работает на компьютере владельца — основная база `student_marketplace` не используется для seed, миграций и тестов (правило в [CODEX_INSTRUCTIONS.md §3](CODEX_INSTRUCTIONS.md#3-что-запрещено-без-согласования)).

## Текст задания: первый запуск

```text
Работай в репозитории Qosyl от актуальной ветки main.
Прочитай AGENTS.md, затем docs/qosyl-improvements/README.md и docs/qosyl-improvements/CODEX_INSTRUCTIONS.md.
Решения владельца в README (раздел «Решения») обязательны и важнее любых рекомендаций в документах.
Исследование и проектирование уже выполнены — не повторяй их и не придумывай свою архитектуру.
Создай ветку improvements/stage1-foundation от main.
Возьми первую невыполненную задачу из docs/qosyl-improvements/TASKS.md (задачи со статусом [-] отменены — пропускай их) и выполни её по docs/qosyl-improvements/IMPLEMENTATION_PLAN.md.
Работай по одной задаче: код, тесты, визуальная проверка, отметка в TASKS.md в том же коммите, отчёт по шаблону из CODEX_INSTRUCTIONS.md §10.
Не пушь в main, не делай деплой, не добавляй зависимости и миграции вне описанных задач.
После каждой задачи остановись и пришли отчёт.
```

## Текст задания: продолжение

```text
Продолжай по docs/qosyl-improvements/TASKS.md: следующая невыполненная задача, те же правила из CODEX_INSTRUCTIONS.md. После задачи — отчёт и остановка.
```

## Текст задания: целый этап

```text
Выполни этап N из docs/qosyl-improvements/TASKS.md целиком, задача за задачей, в ветке improvements/stageN-<кратко> от актуального main (или от ветки предыдущего этапа, если она ещё не влита). После каждой задачи — коммит с отметкой в TASKS.md. В конце этапа пришли сводный отчёт по шаблону CODEX_INSTRUCTIONS.md §10 по каждой задаче. Если задача блокируется — отметь [!] с причиной и переходи к следующей независимой.
```

## Что проверять владельцу после этапа

- Отчёт содержит реальные результаты команд и список непроверенного.
- В TASKS.md отмечены только задачи, у которых выполнены все критерии.
- После QOSYL-006 (палитра Deep Blue/Teal) — просмотреть сайт в светлой и тёмной теме.
- Перед QOSYL-040 и QOSYL-042 (миграции) — проверенная резервная копия (`npm run db:backup -- --verify`).
