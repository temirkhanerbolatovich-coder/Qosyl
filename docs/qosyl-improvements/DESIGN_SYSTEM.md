# Дизайн-система Qosyl: правила для доработок

Этот документ **не создаёт новую палитру**. Утверждённая владельцем палитра — **Deep Blue/Teal** (решение В-2 от 15.11.2026; она же записана в `AGENTS.md` и была реализована 26.10.2026, коммит `ac99717`). 14.11.2026 код перевели на Indigo «Qosyl Modern» (коммит `d98627f`) — **это отменено задачей QOSYL-006 (выполнена 15.11.2026)**: значения ниже действуют в коде. Единственные отличия от коммита `ac99717` — `action-border` и наведение на вторичную кнопку (см. таблицу и [docs/design-system.md](../design-system.md)). Единственный источник значений — [src/lib/design-tokens.json](../../src/lib/design-tokens.json), генерация — `npm run ui:tokens` (создаёт `src/app/design-tokens.css` и проверяет контраст обеих тем); описание — [docs/design-system.md](../design-system.md) (обновляется в QOSYL-006). Здесь зафиксировано: целевые цвета, какие **недостающие** токены добавить (типографика, поверхности, брейкпоинты, тоны статусов) и правила компонентов.

Характер палитры: глубокий синий (#142D4E) — текст и «вес» интерфейса, бирюзовый (Teal #087F8C) — действия и выбранное состояние, синий info (#2058BA) — справочные статусы. Так действие визуально отделено от информационных меток.

Принципы (порядок важности): **ясность → честность данных → плотность без шума → единообразие → характер**. Запрещено: декоративные градиенты, стекло (`backdrop-filter`) ради эффекта, иллюстрации-заглушки, анимации без причины, радиусы больше 16 px, тени на всём подряд, больше одной primary-кнопки в видимой области.

### 1.3 Дополнительные цвета

Новые акцентные цвета не добавлять. Категории проектов **не кодируются цветом** (сейчас `.category-icon.category-*` даёт каждой категории свой фон с первой буквой — заменить на иконку Lucide в нейтральном тоне, см. §6.4). Причина: 7–11 категорий не различимы цветом для людей с нарушением цветовосприятия и создают визуальный шум.

### 1.4 Тоны статусов (добавить — QOSYL-004)

Все статусы сводятся к **5 тонам**. Тон — это класс `.status[data-tone]`, использующий существующие семантические токены.

| `info`      | `info-*`                                   | `Clock3`                                 | `pending_moderation`, `assigned`                             | `pending`, `active` («На рассмотрении») |

| `success`   | `success-*`                                | `CheckCircle2`                           | `published` («Открыт для откликов»), `accepted`, `completed` | `selected` («Вы выбраны»)               |

## 2. Типографика

Шрифты не меняются: **Manrope** (заголовки, числа), **Inter** (интерфейс, текст), локальные WOFF2, `font-display: swap`. Казахские буквы, отсутствующие в Manrope, переходят к Inter — не ломать порядок `Manrope → Inter → sans-serif`.

### 2.1 Шкала ролей (добавить токены — QOSYL-002)

Добавить в `design-tokens.json` раздел `typography` и генерировать CSS-переменные `--text-<role>-size`, `--text-<role>-line`, `--text-<role>-weight`. Значения ниже согласованы с текущей документацией (body 16/1.6, H1 32–44, H2 24–32, caption ≥ 12).

| Роль      | Шрифт   | Размер, px (моб → деск) | Line-height | Вес                                       | Где                                                     |
| --------- | ------- | ----------------------- | ----------- | ----------------------------------------- | ------------------------------------------------------- |
| `display` | Manrope | 32 → 48 (clamp)         | 1.12        | 700                                       | Только hero главной                                     |
| `h1`      | Manrope | 28 → 40 (clamp)         | 1.15        | 700                                       | Заголовок страницы, 1 на страницу                       |
| `h2`      | Manrope | 22 → 28                 | 1.25        | 650                                       | Секции страницы                                         |
| `h3`      | Manrope | 18 → 20                 | 1.3         | 650                                       | Заголовок карточки, панели                              |
| `body-lg` | Inter   | 17                      | 1.6         | 400                                       | Описание задачи на детальной странице                   |
| `body`    | Inter   | 16                      | 1.6         | 400                                       | Основной текст, поля ввода (16 px — чтобы iOS не зумил) |
| `body-sm` | Inter   | 14                      | 1.5         | 400/500                                   | Метаданные, подписи полей, кнопки small                 |
| `caption` | Inter   | 12                      | 1.4         | 500                                       | Бейджи, eyebrow, подсказки под полем                    |
| `numeric` | Manrope | как роль-родитель       | —           | 700, `font-variant-numeric: tabular-nums` | Бюджеты, счётчики                                       |

Правила: не задавать `font-size` числом в компонентах и inline-стилях (сейчас есть `style={{ fontSize: 18 }}` в `src/components/dashboard.tsx` — заменить классом роли). Максимальная ширина текстового блока — 72ch. Длинные названия переносятся (`overflow-wrap: anywhere`), не обрезаются, кроме описания в карточке (2 строки, `line-clamp`).

## 3. Отступы, сетка, брейкпоинты

### 3.1 Отступы (существуют)

`--space-4 … --space-96`: 4/8/12/16/20/24/32/40/48/64/80/96. Внутри карточки — 16 (моб) / 20–24 (деск); между карточками в списке — 12 (моб) / 16 (деск); между секциями страницы — 48 (моб) / 64 (деск). Произвольные значения в px запрещены.

### 3.2 Контейнер

Максимум 1280 px, боковые поля 16 px (моб) / 24 px (≥ 768) / 32 px (≥ 1100).

### 3.3 Брейкпоинты (добавить — QOSYL-044)

Сейчас в CSS 10 разных точек (600/700/800/850/900/1024/1100/1440/1600). Целевой набор — 4, в `design-tokens.json → breakpointsPx`, использовать в медиазапросах как комментарий-ссылку (CSS-переменные в `@media` не работают):

| Имя  | Ширина   | Поведение                                                                                                   |
| ---- | -------- | ----------------------------------------------------------------------------------------------------------- |
| `sm` | ≤ 599    | Телефон: одна колонка, нижние панели, меню-кнопка                                                           |
| `md` | 600–899  | Большой телефон/планшет: 2 колонки карточек, меню-кнопка (шапка раскрывается до 900 включительно — уже так) |
| `lg` | 900–1439 | Ноутбук: фильтры сбоку, 2 колонки карточек                                                                  |
| `xl` | ≥ 1440   | Широкий: 3 колонки карточек в каталогах без боковой панели                                                  |

Переход выполняется постепенно: новые и изменяемые правила используют только эти точки; старые меняются при касании файла. Проверка: ширины 320, 375, 390, 768, 1024, 1440, 1920 из UI-набора.

## 4. Радиусы, поверхности, тени

### 4.1 Радиусы (существуют)

`small` 6 — бейджи, теги, чекбоксы; `medium` 10 — кнопки, поля, чипы; `large` 12 — карточки, панели; `xl` 16 — модальные окна и нижние панели (только верхние углы). Чипы фильтров — `medium`, **не pill** (сейчас `category-chip` — капсула; менять при касании, чтобы не смешивать формы).

### 4.2 Поверхности (добавить — QOSYL-002)

Три уровня вместо произвольных теней:

| Уровень   | Фон       | Граница       | Тень                                                                     | Где                                            |
| --------- | --------- | ------------- | ------------------------------------------------------------------------ | ---------------------------------------------- |
| `flat`    | `surface` | `border` 1 px | нет                                                                      | Карточки списков, панели, поля                 |
| `raised`  | `surface` | `border` 1 px | `0 1px 2px var(--shadow-color), 0 4px 12px var(--shadow-color)`          | Hover карточки, выпадающие меню, липкие панели |
| `overlay` | `surface` | нет           | `0 12px 32px var(--shadow-color)` + затемнение фона `rgb(17 24 39 / .4)` | Модальные окна, нижние панели (sheet)          |

Цветная верхняя полоса у карточек (`.project-card` с акцентной границей сверху) — убрать (QOSYL-012): это декоративный элемент без смысла.

## 5. Иконографика

Только **Lucide** (`lucide-react` 1.61). Размеры: 14 (в строке метаданных), 16 (в кнопке), 18–20 (самостоятельная иконка-кнопка), 24 (пустые состояния). `stroke-width` по умолчанию. Иконка-кнопка всегда с `aria-label`, область нажатия ≥ 44×44 px. Декоративные иконки — `aria-hidden="true"`. Логотип — только `public/brand/qosyl-logo.jpg` без изменений (см. AGENTS.md).

## 6. Компоненты

Все компоненты уже имеют базовые классы в `src/app/design-system.css`. Новый UI-kit не добавлять; новые сложные виджеты (диалог, sheet) — нативный `<dialog>` или существующий паттерн нижней панели фильтров возможностей.

### 6.1 Кнопки (`.button`)

| Вариант       | Класс                               | Когда                                   |
| ------------- | ----------------------------------- | --------------------------------------- |
| primary       | `.button`                           | Одно главное действие в видимой области |
| secondary     | `.button.secondary`                 | Альтернативное действие                 |
| outline/ghost | `.button.outline` / `.button.ghost` | Третичные действия, в тулбарах          |
| destructive   | `.button.danger`                    | Необратимое — всегда с подтверждением   |
| link          | `.text-link`                        | Навигация в тексте                      |

Размеры: default — высота 44 px; `small` — 36 px (только в плотных списках на десктопе, на телефоне область нажатия всё равно ≥ 44 через padding). Состояния: default / hover (`action-hover`, 100 ms) / active (scale .98) / focus-visible (кольцо `focus`) / disabled (приглушённая поверхность без снижения opacity текста; **с причиной рядом**, если причина не очевидна) / loading (спиннер 16 px вместо иконки, текст остаётся, `aria-busy`). Двойная отправка блокируется `useAction().busy`.

### 6.2 Поля ввода (`.field`)

Метка всегда над полем (не только placeholder). Подсказка — `caption` под полем. Ошибка — текст `error` + иконка `AlertCircle` под полем, `aria-invalid`, `aria-describedby`; поле получает границу `error-border`. Placeholder — пример формата («Например, 15 000»), не значение по умолчанию. Обязательность — слово «необязательно» у необязательных полей (их меньше). Числовые поля денег — `inputmode="numeric"`, отображение с пробелами-разделителями тысяч.

### 6.3 Карточка проекта (`ProjectCard`)

Единый порядок (QOSYL-012):

1. Строка-метка: иконка категории (нейтральная) + название категории · «ДЕМО» (если есть) · справа дата публикации («2 дня назад»).
2. Заголовок `h3`, ссылка на всю карточку (одна ссылка, без отдельного «Подробнее»).
3. Описание: 2 строки.
4. Факты одной строкой: **бюджет** (numeric, крупнее) · часы · формат/город · срок.
5. Теги: до 3 навыков + «Можно без опыта».
6. Нижняя строка (только при наличии данных): «Заказчик проверен» (иконка `ShieldCheck`) · откликов (если решение В-4 = да).

Высота: ≤ 260 px на 375, ≤ 220 px на 1440. Статус «Открыт для откликов» в каталоге не показывать (все карточки каталога открыты) — показывать только в кабинетах.

### 6.4 Карточка пользователя (кандидат, профиль)

Аватар 40 px (существующий `ProfileAvatarImage` или инициал на `surface-elevated`) · имя · заголовок профиля · вуз/курс (если не скрыто) · до 5 навыков · строка доверия: «N подтверждённых работ», «Профиль публичный» → ссылка «Открыть профиль». Никаких рейтингов-звёзд, если отзывов < 3 (показывать «Пока нет отзывов»).

### 6.5 Фильтры

- Десктоп (≥ 900): боковая колонка 280 px, кнопка «Применить» в липкой строке внизу колонки + живой счётчик (как в возможностях — `catalogue-aside`).
- Телефон: кнопка «Фильтры · N» (N — число активных) открывает нижнюю панель (`overlay`, `xl` радиус сверху, 250 ms вход / 200 ms выход), внизу липкие «Сбросить» и «Показать N».
- Над результатами — чипы применённых фильтров с «×» и «Очистить всё».
- Быстрые фильтры — горизонтальная прокручиваемая лента на телефоне (одна строка, не перенос).

### 6.6 Выпадающие списки

Нативный `<select>` для простых списков (сохраняет доступность). Для мультивыбора навыков — не вводить сложный combobox; использовать текстовое поле с подсказками существующих навыков (`<datalist>`) — P2.

### 6.7 Модальные окна и нижние панели

Нативный `<dialog>` с `showModal()` (фокус-ловушка браузера), заголовок `h2`, закрытие по Esc, кнопке «×» и клику по фону; возврат фокуса к источнику. Ширина ≤ 560 px; на телефоне — нижняя панель на всю ширину. Подтверждение необратимого действия: заголовок-вопрос, одна строка последствий, кнопки «Отмена» (secondary, фокус по умолчанию) и действие (danger).

### 6.8 Таблицы

Используются в админке и журнале затрат. На ≤ 899 px — горизонтальная прокрутка внутри контейнера с тенью-подсказкой края, либо преобразование строк в карточки для списков ≤ 5 колонок. Числа выровнены вправо, tabular-nums.

### 6.9 Навигация

- Шапка: логотип · основные разделы · справа меню аккаунта (аватар) и одно primary-действие по роли (гость: «Начать»; студент: нет; заказчик: «Разместить заказ»). Тема и язык — внутри меню «Настройки» (иконка `Settings2`/`Languages`), не два select (QOSYL-007).
- Набор разделов зависит от роли: «Избранное» — только при роли студента.
- Кабинет: вкладки `WorkspaceNav`; на телефоне — горизонтальная лента с градиентом-подсказкой края и автопрокруткой к активной вкладке (QOSYL-034).

### 6.10 Бейджи и теги

- `.badge.demo` — «ДЕМО» (warning-тон, иконка), обязательно на демо-сущностях.
- `.status[data-tone]` — см. §1.4.
- `.tag` — навыки (нейтральный), `.tag.beginner` — «Можно без опыта» (success-тон).
  Не больше 5 бейджей/тегов в строке, остальное «+N».

### 6.11 Уведомления

- **Тосты** (`toast-provider.tsx`, существует): результат действия, 4–6 с, «Отменить» только для реально обратимых действий.
- **Inline-сообщения** (`ActionFeedback`, `.alert`): ошибки форм и сервера — остаются на экране до исправления.
- **Лента уведомлений** в кабинете: отдельный блок/страница со списком, а настройка языка уведомлений — в «Настройках» (QOSYL-024).

### 6.12 Skeleton и загрузка

По умолчанию — приглушение предыдущего содержимого + спиннер, если ожидание > 1 с (существующее правило этапа 0). Skeleton — только там, где он удерживает раскладку при первой загрузке списка (карточки каталога: 3 серые карточки той же высоты). Никогда не показывать «Ничего не найдено» до завершения запроса.

### 6.13 Пустые состояния (`EmptyState`)

Структура: иконка 24 px (нейтральная) · заголовок-ситуация («Подходящих задач пока нет») · одна строка причины/подсказки · одно действие (primary или secondary) · опционально вторичная ссылка. Различать: «пусто совсем» (нет данных в системе), «пусто по фильтрам» (предложить сбросить конкретные фильтры), «пусто у пользователя» (первый шаг).

### 6.14 Ошибки и подтверждения

- Ошибка загрузки: что произошло простыми словами + «Повторить»; введённые данные не теряются.
- «Не найдено / закрыто» — **не ошибка**: отдельное состояние без «Повторить», с действием «К каталогу» и похожими элементами (QOSYL-005).
- Успех: тост или inline-сообщение + следующий шаг («Отклик отправлен. Следите за статусом в «Моих откликах»»).

## 7. Движение

Токены `motion` существуют: fast 100, base 150, slow 250, exit 200, page 400 ms; кривые enter/exit/move. Анимировать только `transform` и `opacity`. Всё отключается при `prefers-reduced-motion: reduce` и встроенном переключателе. Разрешено: hover карточки (raised, 150), нажатие (100), вход панели/диалога (250/200), появление тоста (150). Запрещено: бесконечные циклы, параллакс, анимация появления каждого элемента списка.

## 8. Адаптивность и доступность (обязательные критерии)

- Нет горизонтальной прокрутки страницы на 320–1920 px (`npm run test:ui`).
- Области нажатия ≥ 44×44 px (на десктопе ≥ 24×24 с интервалом — WCAG 2.5.8).
- Видимый фокус у всех интерактивных элементов; порядок табуляции = визуальный.
- Контраст текста ≥ 4.5:1, крупного ≥ 3:1, границ полей ≥ 3:1 (проверяется `npm run ui:tokens`).
- Зум 200% без потери функций.
- Длинные RU/KK строки не ломают раскладку (проверять KK — слова длиннее).
- `lang` у пользовательского контента (`lang="und"` уже используется) сохранять.

## 9. Правила использования

1. Перед созданием компонента найдите существующий класс в `design-system.css`/`globals.css` и компонент в `src/components/platform.tsx`.
2. Новый цвет, размер, отступ, радиус, тень — только через `design-tokens.json` + `npm run ui:tokens`.
3. Один экран — одна primary-кнопка в видимой области.
4. Числа: бюджет — `money()`, даты — `date()` из `src/lib/labels.ts`; не форматировать вручную. Статус `active` отклика показывать как «На рассмотрении» (сейчас «Активен») — правка подписи в `labels.ts` и KK-словаре в рамках QOSYL-004.
5. Каждая новая строка интерфейса — в RU и KK одновременно.
6. Изменения дизайн-системы фиксируются в [docs/design-system.md](../design-system.md) (раздел с датой) — этот файл остаётся инструкцией доработок.
