# Спецификация интерфейса

Для каждой страницы: текущее состояние (кратко, с доказательством в [PRODUCT_AUDIT.md](PRODUCT_AUDIT.md)), целевая структура сверху вниз, состояния, поведение, мобильная версия, задачи. Визуальные значения — только из [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md). Маршруты не меняются.

Обозначения в схемах: `[Primary]` — primary-кнопка, `[Sec]` — secondary, `(чип)`, `«текст»`.

Терминология (решение В-1): подписи разделов **не переименовываются** — в навигации и заголовках остаются «Проекты», «Каталог проектов», «К каталогу проектов». Слово «задача» в схемах — описательное и используется там, где оно уже есть в интерфейсе («Найди задачу», «Разместить задачу», «Задача» на странице проекта). Цвета — палитра Deep Blue/Teal (решение В-2, QOSYL-006).

## 1. Глобальные элементы

### 1.1 Шапка (`src/components/site-header.tsx`) — QOSYL-007

**≥ 901 px:**

```
[Лого Qosyl] Возможности  Поступление  Проекты  Как это работает      [⚙ Настройки] [Аватар ▾] [Primary по роли]
```

- Порядок и подписи разделов — как сейчас (решение В-1: возможности главные, без переименований).
- «⚙ Настройки» — кнопка-меню: Тема (Светлая/Тёмная/Система — радио), Язык (Русский/Қазақша — радио), Анимации (переключатель, существующий). Меню закрывается Esc и кликом вне; фокус возвращается на кнопку.
- «Аватар ▾» (вошедший): Мой кабинет, Профиль, Избранное (только студент), Настройки уведомлений, Выйти.
- Primary по роли: гость «Начать»; заказчик «Разместить заказ»; студент — нет.

**≤ 900 px:** текущее поведение (логотип, иконка избранного для студента, кнопка «Меню», раскрывающийся список) сохраняется; внутри меню — те же группы.

### 1.2 Баннер пилота (`layout-copy.tsx`) — QOSYL-008

Одна строка на ≥ 768 px; на телефоне две фразы с переносом по фразе, разделитель «·» только внутри строки. Высота ≤ 48 px на 375.

### 1.3 Подвал

Без изменений.

### 1.4 Тосты, диалоги, нижние панели

См. DESIGN_SYSTEM §6.7, §6.11. Тосты не перекрывают мобильные панели действий (правило `body:has(.detail-actions) .toast-region` уже есть — расширить на новую панель проекта).

## 2. Главная (`/`, `HomeScreen` в `src/components/catalog.tsx`) — QOSYL-036 (В-1)

**Сейчас:** hero про возможности + поиск возможностей + чипы типов → блок возможностей → «Поступление» → «Проекты от заказчиков» (на 1788 px из 2273 на 1440) — только текст и одна кнопка «Найти проект», «Разместить задачу» — текстовая ссылка.

**Решение В-1:** возможности — главное направление. Hero, поиск, чипы типов, блок возможностей и «Поступление» **сохраняются в текущем порядке**. Меняется только блок «Проекты от заказчиков»:

```
h2 Проекты от заказчиков                                     Все проекты →
«Пилот 18+. Выберите задачу или предложите свою. Расчёты проходят вне платформы…» (существующий текст)
┌ ProjectCard ┐ ┌ ProjectCard ┐ ┌ ProjectCard ┐     ← до 3 свежих, только если есть открытые
Как это работает для бизнеса: 1 Опишите задачу по шаблону · 2 Модерация · 3 Выберите исполнителя и примите результат
[Sec Найти проект]  [Sec Разместить задачу]
```

- Карточки: `view=catalog&sort=newest`, первые 3; 1440 — 3 в ряд, 768 — 2, 375 — список из 3 (не горизонтальная лента — её плохо обнаруживают).
- Нет открытых проектов или ошибка загрузки → карточки не рендерятся, текст и обе кнопки остаются.

**Мобильная:** кнопки «Найти проект» и «Разместить задачу» — на всю ширину друг под другом; шаги «Как это работает» — нумерованный список.

## 6. Публикация заказа (`/client/projects/new`, `/client/projects/[id]/edit`) — QOSYL-020, 021, 022, 045 (В-9)

**Решение В-9:** мастер и одна страница совмещены — одна форма, два режима отображения, переключатель всегда доступен.

**Структура (≥ 900 px):** две колонки: форма (≤ 720 px) + справа липкий предпросмотр карточки и чек-лист полноты (в обоих режимах).

Режим «По шагам» (по умолчанию для нового заказа):

```
Кабинет заказчика / Новая задача
Вид формы: (● По шагам) (○ Все поля)
Шаг 1 из 4 ●───○───○───○   Суть · Результат · Условия · Проверка
┌ Шаг 1. Суть задачи ─────────────────────┐  ┌ Как увидит студент ┐
│ Шаблон по направлению [▾] (необязательно)│  │ [ProjectCard]      │
│   превью шаблона, [Применить]            │  ├ Готовность ТЗ ─────┤
│ Название задачи                          │  │ ✓ Название         │
│ Категория [▾]   Уровень [▾]              │  │ ○ Результат        │
│                                          │  │ ○ ≥2 критерия      │
│ [Sec Сохранить черновик]   [Primary Далее]│  │ …                  │
└──────────────────────────────────────────┘  └────────────────────┘
```

Режим «Все поля» (по умолчанию для редактирования):

```
Вид формы: (○ По шагам) (● Все поля)
Оглавление: Суть · Результат · Условия · Проверка       (якорные ссылки, липкие на десктопе)
§ Суть задачи … § Результат … § Условия … § Проверка: предпросмотр, чек-лист, шкала статуса, действия
```

- **Шаг/раздел «Результат»:** «Какую проблему решаем?», «Описание и границы» (подсказка про персональные данные — существующая), «Ожидаемый результат», «Критерии приёмки» (по одному на строку; счётчик «2 из 15»), «Навыки» (через запятую + подсказки).
- **Шаг/раздел «Условия»:** «Бюджет за весь результат, ₸» (placeholder «Например, 15 000», подсказка «Платёж — напрямую, вне платформы»), «Трудоёмкость, часов», «Срок сдачи», «Предпочтительные дни и время», «Формат» (радио-кнопки Удалённо/Очно/Гибрид вместо select), «Город» и «Точная локация (закрытая)» — только для Очно/Гибрид, «Контакт после назначения» (подсказка «Виден только исполнителю после согласования условий»).
- **Шаг/раздел «Проверка»:** сокращённый предпросмотр страницы, чек-лист, предупреждение пилота 18+ (существующее), шкала «Черновик → На модерации → Опубликован», действия `[Sec Сохранить черновик]` `[Primary Отправить на модерацию]`.
- Переключатель «Вид формы» — радиогруппа; переключение не теряет ввод и ошибки; в «По шагам» открывается шаг с первой ошибкой, иначе первый незаполненный. Выбор запоминается (`localStorage`, только удобство).
- Индикатор шагов — `<ol>` с `aria-current="step"`; клик по пройденному шагу — переход.
- **≤ 899 px:** одна колонка; предпросмотр и чек-лист — сворачиваемый блок «Предпросмотр и готовность» над кнопками; в «По шагам» кнопки «Назад/Далее» — липкая нижняя строка; в «Все поля» — липкая строка «Сохранить черновик / Отправить на модерацию».

**Состояния:** ошибка поля — под полем + переход к шагу (в «По шагам») или прокрутка к полю (в «Все поля»); ошибка сохранения — `ActionFeedback` над кнопками, ввод сохранён; сессия истекла — сообщение с входом и `next`; сохранено — тост.

## 11. Авторизация и onboarding — QOSYL-018

- `/auth/register?next=…`, `/auth/login?next=…`: над формой — контекст, если `next` ведёт на задачу: «Чтобы откликнуться на «<название>», создайте аккаунт» (название — из публичного API; при ошибке — общий текст).

- Ошибка `target-size` у чекбокса согласия (аудит 04.11, A01) — проверить, что исправлено; если нет — увеличить область нажатия до 24×24 с интервалом.

## 12. Мобильный опыт — сквозные правила

Не уменьшенный десктоп, а отдельная иерархия:

1. **Главное действие у большого пальца:** нижние панели действий на страницах задачи и возможности, липкие «Далее»/«Сохранить» в формах.
2. **Первый экран = содержание, а не управление:** в каталогах до первой карточки ≤ 2 строки управления (поиск; строка «Фильтры · счётчик · сортировка»).
3. **Одна колонка, прогрессивное раскрытие:** вторичная информация (памятка безопасности, пояснения знаков, подробные условия) — в `<details>`.
4. **Поля:** `font-size` 16 px, правильные `inputmode`/`type` (`numeric`, `email`, `date`), `autocomplete`.
5. **Области нажатия ≥ 44 px**, между соседними — ≥ 8 px.
6. **Горизонтальная прокрутка** — только для лент чипов/вкладок, всегда с визуальной подсказкой края.
7. **Безопасные зоны:** `env(safe-area-inset-bottom)` у нижних панелей (уже используется в `.detail-actions`).
8. **Сеть:** состояния загрузки не блокируют уже показанный контент; повтор не теряет ввод.
