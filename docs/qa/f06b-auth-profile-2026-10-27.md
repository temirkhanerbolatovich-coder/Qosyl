# F06b — авторизация и настройки профиля RU/KK

Статус: F06b принят локально. Объём: login/register/forgot/reset/verify, onboarding и настройки исполнителя/заказчика. Это продолжение F06a, не завершение полного F06.

## Изменения и границы

- Все статические подписи, подсказки, действия и состояния указанных форм имеют RU/KK пары. Язык обновляется без перемонтирования формы.
- Ошибки и успех хранят идентичность состояния и переводятся при отображении. Известные коды Better Auth и code/status профиля сопоставляются явно; неизвестные ответы и причины модерации сохраняются как исходный текст с `lang="und"`.
- Смена языка сохраняет поля, согласия, выбранные форматы, внешние работы и URL, не отправляя POST. API payloads, роли, ограничения паролей, согласия и серверные проверки не менялись.
- Новых зависимостей, миграций, публикации или внешней рассылки нет. Использована существующая схема LocaleProvider; отдельный ADR не нужен.

## Проверки

- `npm run build`, `npm run typecheck`, `npm run lint`, `npm run api:check` — успешно. OpenAPI соответствует runtime validators.
- `npm test` — 426/426, 34 файла. Новые unit-проверки покрывают повторный перевод ошибок, безопасный fallback, сохранение неизвестных сообщений и приоритет 429/5xx.
- Фокусный `npx playwright test tests/e2e/auth-locale.spec.ts` — 6/6. Реальные регистрация, сохранение обеих ролей и сброс пароля выполняются в управляемой изолированной БД; сброс отзывает сессии, повторный и просроченный токены отклоняются.
- Итоговый `npm run test:e2e` — 41/41 за 3,6 минуты; включая прежние сценарии биржи, файлов, модерации и настоящий rate-limit входа. Лог `.local/f06b-e2e-final.log`.
- Итоговый `npm run test:ui` — 196/196, без skipped/flaky, 168 базовых audit-состояний и проверки loading/error/keyboard; serious/critical axe и overflow не обнаружены. Лог `.local/f06b-ui-final.log`. `git diff --check`, форматирование изменённых TS/TSX и локальные ссылки в документации проверены.
- Синтетические перехваты отдельно проверяют pending, ошибки сети/валидации/доступа/сервера и успех. Они не считаются реальным сохранением или доставкой письма. Для профиля проверено, что синтетический сценарий не изменил данные в БД.
- 16 сочетаний RU/KK, light/dark и 375/768/1440/1920 px распределены между регистрацией и двумя профилями: axe без serious/critical, без горизонтального overflow. Это выборка, не полное декартово произведение всех экранов.
- Вручную просмотрены 7 снимков: register RU light 375; student RU light 768; client RU light 1440; client KK light 375 и 1920; register KK dark 375; student KK dark 768. На просмотренных снимках нет перекрытия подписей/кнопок и обрезания блоков. Длинные значения однострочных input прокручиваются штатно.

## Исправления проверочного набора

Первый фокусный прогон: 4/6. Reset-заголовок и поле имели одинаковое доступное имя; селектор уточнён до input. Контраст измерялся во время смены темы; добавлено ограниченное ожидание завершения конечных анимаций, без отключения axe. Повторный прогон: 6/6.

Первый общий прогон: 19 прошли, 1 ошибка setup, 21 не запущен. Общие фикстуры достигли настоящего лимита регистрации 6/мин. Подготовка workflow-аккаунтов теперь при 429 один раз ожидает проверенный `X-Retry-After` (0–60 секунд) и повторяет регистрацию. Защита приложения и конфигурация лимита не изменены; остальные ошибки не повторяются автоматически.

Первый строгий UI-прогон: 195/196. После повторного поиска возможностей axe обнаружил отсутствующий document title во время клиентской навигации. В `states.spec.ts` добавлено ограниченное ожидание непустого заголовка до аудита; правило axe не исключается, постоянное отсутствие title остаётся ошибкой. Заголовок страницы по-прежнему задаётся metadata корневого layout.

## Оставшееся

Кабинеты, рабочая область, формы заказа, публичные профили и административные экраны ещё не полностью переведены. Письма, юридические тексты и неизвестные серверные сообщения остаются в исходном языке. Native validation зависит от языка браузера. Verify-форма проверена, но реальный production email verification/SMTP не проверялся: локальный режим отключает подтверждение почты. Reset использует настоящий локальный mail transport; токены не включены в отчёт.

Редакторская проверка казахского носителем языка, реальные устройства/диктор/Firefox/Safari, native zoom и измерение производительности остаются отдельными задачами. Следующий пакет — F06c, кабинеты и рабочая область.
