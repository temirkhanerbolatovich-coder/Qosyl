# Отчёт об инфраструктуре UI Quality

Дата: 26 октября 2026. Первый этап завершён: исследование, база знаний, skill, browser QA и проектная спецификация. Существующий интерфейс и бизнес-логика не изменялись. Это подготовка к улучшениям, не приёмка редизайна.

## Изученные материалы

Полностью прочитан пользовательский `Codex_UI_UX_Engineering_Report_2026.docx`: 333 непустых абзаца с таблицами, все разделы 1–14 и промпты A–E, 56 внешних ссылок. Исходник 52 287 байт остался неизменным; его SHA-256 и описание извлечения сохранены в [базе знаний](../ui-quality/README.md). [Текстовая копия](../../outputs/ui-quality/report-extracted.txt) позволяет повторно проверить охват, не полагаясь на память чата.

Изучены предметный подход Anthropic frontend-design, текущие Vercel interface guidelines и React performance priorities, OpenAI skills/AGENTS и опубликованный frontend-app-builder, Playwright accessibility, применимые критерии WCAG/APG, responsive/CSS, Web Vitals, открытые материалы Primer/Carbon/Atlassian и назначение остальных инструментов. Свои выводы адаптированы к существующему коду Qosyl.

Все 56 URL проверены на доступность: 55 HTTP 200, Figma Community HTTP 403. Даты, переадресации, заголовки и хеши ответа — [source-status.json](../../outputs/ui-quality/source-status.json). Отдельно сохранены engines/peerDependencies/лицензии 18 npm-пакетов. В [реестре](../ui-references.md) указана глубина проверки: профильное чтение не смешано с проверкой главной страницы. Не прочитаны все вложенные руководства всех фреймворков, закрытые коллекции, платные книги и все внутренние экраны перечисленных продуктов. Такое утверждение не следует из доступности URL.

## Совместимость и выбор

Подтверждён существующий стек: Node 24.12.0, npm, Windows PowerShell; Next 16.4.3, React/DOM 19.3.1, TS 5.9.3, Tailwind/PostCSS 4.3.3, Lucide 1.61.0, Playwright 1.64.1. CSS-система собственная, не требует добавления второго кита. Все решения и альтернативы — [stack-decision.md](../stack-decision.md), [ADR-009](../../11_Reports/Decisions/ADR-009-ui-quality-infrastructure.md).

Существенные уточнения к отчёту:

- `@tremor/react@3.18.7` заявляет React ^18, что не включает установленный React 19. Не установлен; peer-конфликт не обходился флагами.
- Polaris URL теперь перенаправляет в Shopify API/Web Components references; нельзя автоматически трактовать его как прежний универсальный React-kit.
- Исследованный TanStack Table latest — major 9; старые примеры v8 нельзя переносить без сверки API. Вторичная попытка открыть `/latest/docs/introduction` вернула 404, рабочим исходным адресом остаётся `/table/latest`.
- Tailwind уже v4; общий docs URL открывает Vite guide, для Qosyl отдельно проверен Next.js guide.
- Опубликованный frontend-app-builder задаёт собственный Image Gen/new-app/redesign workflow. На этом этапе он не установлен и не применён как инструкция менять продукт.
- Vercel рекомендации рассматриваются критически: английский Title Case, запрет autocomplete для всех не-auth полей и универсальная virtualization по числу строк не становятся обязательными правилами Qosyl.

## Что установлено

Одна devDependency: **@axe-core/playwright 4.14.0**, MPL-2.0. Node >=22.12 и playwright-core >=1 совместимы с текущей средой; реально установленный Playwright core 1.64.1 переиспользован. npm сообщил: added 1 package, audit 599 packages, 0 vulnerabilities. Runtime dependencies не изменились. UI kits, Motion, Table/Virtual, Storybook, дополнительные шрифты и декоративные каталоги не устанавливались.

Для запуска официального skill-validator понадобился PyYAML: его не было ни в системном, ни в bundled Python. Создан изолированный `.local/ui-skill-validation/`, установлен **PyYAML 6.0.3**, MIT, без изменения глобального Python. Валидатор после этого сообщил `Skill is valid!`. Первоначальная ошибка импорта не скрывается и не выдаётся за успешную проверку.

## Что настроено

- `.agents/skills/ui-quality/SKILL.md`, metadata `agents/openai.yaml`; короткий Qosyl AGENTS и указатель AGENTS в родительском каталоге текущего чата. Существующего физического AGENTS в этих каталогах до работы не было; пользовательские инженерные требования остаются приоритетными.
- Codex CLI 0.164.0-alpha.11.1 через локальный app-server `skills/list` действительно обнаружил `ui-quality`, scope=repo, enabled=true. [Свидетельство](../../outputs/ui-quality/skill-discovery.json). Агентные задачи/LLM turns при проверке не запускались, аккаунты/настройки не менялись. Обновление селектора Desktop отдельно не проверено; открывать Qosyl как корень проекта.
- `playwright.ui.config.ts`: четыре ширины и существующий изолированный E2E startup. Профили baseline/enforced сохраняют отдельные артефакты, чтобы строгий тест не стирал исходные наблюдения.
- `npm run test:ui:baseline`: снимки и axe-наблюдения пяти маршрутов/ролей; не объявляет существующие accessibility-дефекты исправленными.
- `npm run test:ui`: блокирует serious/critical axe и page overflow. Браузер работает в отдельном тестовом контексте; пользовательский профиль и сессии Meta не используются.
- `npm run ui:tokens`: проверяет девять контрастных пар предложенной дизайн-системы. Токены являются документацией и не импортируются в `src`.
- JSON-сводки, HTML/PNG/trace-артефакты, процедуры повтора и ограничения.

Playwright MCP и Chrome DevTools MCP изучены, но не подключены: для текущей задачи работоспособен существующий Playwright Test, дублирующие серверы не нужны. Figma MCP/plugin не подключён и не авторизован. Глобальный config.toml и настройки доступа к браузеру не менялись. Наличие MCP-описания в отчёте не доказывает доступность инструмента в текущей сессии.

## Результаты проверок

| Проверка | Фактический результат |
| --- | --- |
| `npm test` | 303/303, 22 файла |
| `npm run lint` | Успешно |
| `npm run typecheck` | Успешно |
| `npm run ui:tokens` | 9/9 пар; минимальный текстовый контраст в предложенных парах 5.046:1 |
| `npm run test:ui:baseline` | 20/20 проб успешно собрали наблюдения; 5 экранов × 4 ширины, без page overflow |
| Public route runtime | В проверенных public-пробах нет console errors, pageerror и ответов >=400 |
| Keyboard subset | Skip link на login получает focus; mobile menu студента работает на 375 px |
| `npm run test:ui -- --project=chromium-375 --grep 'home:'` | Ожидаемо FAIL: воспроизведены два существующих типа serious axe issues; strict gate не отключён |
| Skill validator / CLI discovery | Валидный формат; реально обнаружен включённый repo skill |
| Сохранность | Все 126 файлов src без изменения хеша; runtime dependencies и исходный DOCX сохранены |

Первый инфраструктурный прогон имел 19/20 из-за ошибочного предположения теста о hamburger на 768 px. Код CSS показывает breakpoint 600: исправлен только тест, приложение не менялось. Финальный baseline прошёл 20/20. Это не скрытие UI дефекта и не изменение breakpoint ради теста.

Повторный production build не выполнялся: исходники приложения не менялись, использована готовая рабочая production-сборка. Полные 22 функциональных E2E и 30 content integration на этом этапе не повторялись; их предыдущие результаты не представлены как новая проверка. Развёртывание, реальные публикации, очистка основной БД и платные сервисы не выполнялись.

## Найденные проблемы и план

**UI-001 High:** accessible name логотипа не содержит весь видимый текст. **UI-002 High:** текст trust-блока главной имеет контраст 3.8:1. Детальные reproduction/targets и ещё четыре визуальных/поддерживаемостных наблюдения — [ui-audit.md](../ui-audit.md). Исправления не внесены согласно границе первого этапа.

Подготовлены [дизайн-система](../design-system.md), [стандарты вёрстки](../frontend-standards.md), [чек-лист](../ui-quality-checklist.md), [поэтапный план](../ui-improvement-plan.md). Выбрана предметная «Рабочая биржа» с существующим синим акцентом, более ясной иерархией данных и отдельной плотностью admin. Альтернативы рассмотрены, обязательная смена цвета/шрифта не навязана. При изменении продуктового приоритета пользователем план пересматривается; пример marketplace из отчёта не отменяет развитие общего поиска возможностей.

Следующая рекомендуемая задача: исправить UI-001/UI-002, затем один эталонный `/projects` с проверкой сценариев/четырёх ширин. Только после его приёмки масштабировать компоненты на остальные маршруты.

## Что остаётся непроверенным

Полная keyboard/screen reader проверка, zoom/reflow, touch на настоящем устройстве, Safari/Firefox, client/admin и workspace state matrix, нестандартные длинные RU/KZ данные, field CWV, Lighthouse, нагрузка и пользовательское тестирование. Нет доступа к закрытым Figma/Mobbin/Refero материалам; не подтверждены тарифные возможности Figma. Не заявлены WCAG-conformance, полная совместимость каждого неустановленного пакета, независимый аудит другим специалистом или оценка дизайна 10/10.
