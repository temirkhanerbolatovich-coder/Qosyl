# Приёмка этапа 3: закрытый сбор возможностей

Дата: 26.10.2026. Проверялось локальное приложение Qosyl на PostgreSQL 18; внешняя публикация не включалась. Этап 3 завершён в указанном ниже объёме. Следующий этап — редакционные решения и публичная лента.

## Реализовано

- Отдельные GET/POST `/api/admin/content`, пять административных действий, строгие request/response схемы и OpenAPI. Основные 30 RPC-команд и 10 видов чтения сохранены.
- Реестр ручных/RSS-источников с доменом, основанием использования, расписанием и выключателями. Вкладка «Сбор возможностей», ручная форма, закрытые материалы и журнал запусков.
- RSS/Atom, plain-text нормализация, канонический URL, даты с `null` для неизвестного, детерминированная оценка, идентичность внутри источника и неизменяемые редакции. A→B→A сохраняет три редакции; повтор текущей редакции — дубль.
- Worker под общим supervisor, короткая транзакция claim, lease 120 секунд, одна активная задача на источник, backoff с Retry-After, остановка источника после пяти ошибок. Отключение перед фиксацией запрещает сохранение полученных материалов.
- HTTPS/443, точный домен, проверка всех DNS-адресов и закрепление адреса при TLS, проверка каждого redirect, запрет private/reserved IP, лимиты 10 секунд/1 МиБ/3 перехода, запрет XML DTD/ENTITY и HTML/script в сохраняемом тексте.
- Шесть самостоятельных таблиц контента; Project и публичный каталог не используются для импортированных публикаций. Ни один новый материал не публикуется автоматически.

Сервисные сценарии проверяют роли и свежий статус аккаунта, запрет записи при выключении, повтор ручного ввода, URL длиной 2001 → 400, новые редакции и запрет возрождения terminal-материалов. Два worker реально перекрываются во время заблокированного fetch: второй не делает сетевой запрос; остаются один run, один материал и одна редакция. Проверены 429/backoff, следующий здоровый источник, пятая ошибка, обе гонки выключения и восстановление просроченного lease.

E2E использует настоящие HTTP/БД/браузер: гостю 401, студенту 403, чужой Origin 403, неправильный Content-Type 415, дробная страница 400. Через UI на 390 px создаётся выключенный источник, включаются флаги, сохраняется материал; API подтверждает дубль и вторую редакцию. Горизонтального переполнения нет. Прежний полный цикл заказа и покрытие всех RPC остаются успешными.

Postman CLI не установлен; Postman simulation не выполнялась. Внешний провайдер в автоматических transport-тестах заменён локальной HTTPS-fixture с настоящим сертификатом и проверкой TLS. В production нет обхода TLS или разрешения private IP. Проверка зависимостей при установке `fast-xml-parser@5.11.2`: npm audit сообщил 0 уязвимостей; это результат на момент установки, не обещание будущего состояния.

Первый создал 50 материалов/50 редакций; второй получил идентичную ленту и вернул 50 дублей, 0 новых материалов и 0 новых редакций. Все записи остались `pending_review`. Лента выбрана для проверки совместимости RSS; она не доказывает пригодность для аудитории Казахстана, актуальность возможностей или спрос бизнеса. Проверка [условий MIT News](https://news.mit.edu/terms-of-use) записана отдельно; публичное повторное использование требует редакционного решения. Изображения и полные статьи не импортируются.

## Основная БД и локальный запуск

Применены две forward-миграции: `20261026120000_content_intake` и `20261026121000_content_revision_occurrences`. Первая добавляет таблицы и ограничения; вторая разрешает повтор hash у разных номеров редакций при A→B→A. Уже применённая первая миграция не переписывалась.

До и после созданы private backup в `.local/backups`, каждая копия восстановлена в отдельную временную БД и полностью сверена. До: 26 таблиц, после: 32. **Все 25 прежних прикладных таблиц, 70 строк, совпали по числу строк и SHA256.** Исключена только ожидаемо изменённая `_prisma_migrations`. [Результат сравнения](../../outputs/content-intake/migration-check.json). Копии: `2026-10-26T10-23-38.973Z-3f1f30` и `2026-10-26T10-26-30.809Z-a844fd`; архивы содержат приватные данные и не публикуются.

Web и оба worker перезапущены через supervisor. На `http://localhost:3000` health 200, административное чтение 200. Основной модуль выключен, источников/материалов/запусков контента 0; настоящие и синтетические импорты выполнялись только в E2E-БД.
