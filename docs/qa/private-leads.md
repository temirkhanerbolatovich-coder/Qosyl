# Приёмка: ручной контур приватных лидов

Дата: 26.10.2026. Реализованы Q22/Q23 и ручная передача этапа 5. Это локальная техническая приёмка: внешние контакты не выполнялись, реальные лиды/согласия не заявляются. Социальные адаптеры Q24 не подключались.

## Реализовано

- Закрытая вкладка admin «Лиды и обсуждения»: ручное добавление, тип, источник, ответственный, срок, фильтры и история.
- Проверка, запись итога ручного контакта, запись согласия конкретного заказчика, отзыв передачи, отказ/архив, возврат на проверку, правки до проверки и заметки.
- Числовая версия и append-only события с автором/временем. Повтор источника не создаёт дубль и не возрождает закрытую запись.
- Заказчик видит только собственную ограниченную передачу. Бюджет, срок, результат и критерии он заполняет в обычной форме; требуется явное подтверждение.
- Единственный draft через существующий projectsCommands(createProject), атомарно с Lead-связью и событием. Идентичный повтор возвращает тот же проект; изменённый запрос конфликтует. Прежняя модерация обязательна.
- Три новых пути API, общий OpenAPI, две таблицы Lead/LeadEvent, SQL-защита идентичности/истории/версии и связи с проектом своего владельца. Новых зависимостей нет.

Финальная проверка после исправления панели: выбранная карточка остаётся доступной, даже если запись находится вне текущей страницы/фильтра. Повторно прошли build, lint, typecheck, api:check, Prettier и отдельный браузерный сценарий `npm run test:e2e -- --grep 'приватный лид'` — 1/1. Полные 21 E2E и остальные наборы выше выполнены до этой небольшой правки представления; повтор полного набора после неё не заявляется. Первая попытка повторного E2E остановилась до запуска теста из-за выключенного PostgreSQL; существующая локальная БД запущена штатной командой без сброса данных, повтор успешен.

Интеграции проверяют свежие роли/блокировку admin и client, закрытость от студента/чужого клиента, canonical URL, повтор закрытого кандидата, запрет пропуска стадий, отсутствие Project до действия владельца, только draft после него, идентичные/изменённые повторы, отзыв/expiry, обсуждение без проекта, гонки решений/конверсий, правки/переназначение/возврат и историю более 20 событий.

SQL-проверки выполняются в отдельных откатываемых транзакциях. Проверены запрет изменения исходной идентичности/удаления, +1 версия, стадии и полное основание согласия, FK владельца проекта, неизменяемая конверсия, append-only/unique event version и UTC-default при INSERT под Pacific/Auckland. Серверные тесты сохраняют синтетическую историю, не удаляют и не переписывают пользовательские данные.

Новый E2E проходит настоящий интерфейс: admin добавляет кандидат → проверяет → записывает ручной контакт и основание согласия → нужный client открывает свою передачу → бюджет изначально пуст → заполняет полное ТЗ и checkbox → получает draft → повтор POST возвращает тот же ID → обычная отправка на модерацию и публикация. До создания draft число проектов не меняется. Проверены 401 guest, 403 другой роли, 400 плохого фильтра/страницы, 403 чужого Origin, 415 неправильного Content-Type, 404 чужого клиента, 409 устаревшей версии и запрет закрывать связанный заказ через Lead. Старые 30 RPC-команд и 10 видов чтения сохраняют полное покрытие.

Postman CLI недоступен. Проверки выполнены штатным OpenAPI, Node/Vitest, реальным PostgreSQL и HTTP/Playwright; не выдаются за Postman simulation. Новый модуль вообще не вызывает внешних провайдеров. Сообщения людям, аккаунты социальных сетей и SMTP-отправка в сценарии не использовались.

## Что остаётся

Ручной контур завершён; весь этап 5 с социальными адаптерами не объявляется завершённым. Для Q24 нужен конкретный канал, официальный доступ, условия, квоты, стоимость и отдельный тест включения/отказа. Полезность настоящих бизнес-запросов, фактический контакт и достаточность согласия подтверждает оператор в реальном пилоте.

Не реализованы автоматический поиск/скрейпинг, отправка сообщений, массовые комментарии, отдельная роль оператора вместо admin, полнотекстовый поиск пользователей/лидов, массовые операции и retention/privacy-процедура. Варианты пользователей ограничены сотней, известный ID клиента можно ввести вручную. Исходные URL/тип не редактируются; описание исправляется до проверки. Обсуждения не конвертируются в Project. Юридическая/личностная верификация внешнего согласия, нагрузка, другие браузеры и публичный production этим этапом не подтверждаются.
