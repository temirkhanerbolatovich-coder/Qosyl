# Профиль: заголовок и проверка миграции

29.10.2026. Это приёмка части фазы 1, а не завершение всего ТЗ.

Необязательный заголовок до 120 символов сохраняется через действующий self-profile API с прежними сессией, origin, транзакцией и аудитом. При отсутствии поля в старом клиенте значение сохраняется. Форма RU/KK использует текущие компоненты и токены. Публичный профиль показывает заголовок только при общей публичности; email не добавляется в публичную проекцию.

## Данные

`npm run test:profile:migration`: в новой одноразовой БД применены прежние SQL-миграции, добавлен профиль с кириллицей и навыками, затем новая миграция. Проверены полное совпадение прежних полей, пустое значение по умолчанию, запись заголовка и откат схемы. Одноразовая БД удалена. Основная база этим тестом не затрагивается.

`npm run db:backup -- --verify`: создана копия `.local/backups/2026-10-29T01-06-24.286Z-97c278`, восстановление в отдельную БД подтвердило совпадение контрольных сумм и числа строк всех 40 таблиц. После этого `npm run db:migrate` применил единственную ожидавшую миграцию `20261029010000_student_headline` к локальной базе. Сброс и повторный seed основной базы не выполнялись.

Откат: сначала экспортировать новые заголовки в защищённую копию, затем вернуть прежний код; удаление столбца уничтожает только новые значения и допустимо после их сохранения. Штатно оставлять аддитивный столбец при откате кода безопаснее, чем удалять его.
