# Проверка организации API и БД

Дата: 25.10.2026. Рабочий каталог: Qosyl. Запрос владельца: упорядочить API, разграничение доступа и БД. Это отдельное техническое изменение после реорганизации файлов.

## Что изменено

- 27 команд выделены из монолитного marketplace в шесть групп; чтения разделены на public/account/admin. Существующие URL и параметры сохранены.
- Профильная транзакция вынесена из HTTP route в серверный service. Ошибки получения сессии/БД теперь обрабатываются в JSON-контракте; все ответы профиля и биржи имеют no-store.
- Общая обработка JSON проверяет точный media type и фактический объём потока. Ошибки дополнены стабильным code; исходное поле error сохраняется.
- Каталог проверяет диапазоны, перечисления, целые страницы, длины текста, календарные даты и порядок бюджета. Сортировка имеет стабильный вторичный ID.
- Из admin.projects исключены приватные адрес/контакт. Признак canApply учитывает истечение срока, блокировку заказчика и выключение demo даже для пользователя admin+student.
- Серверные модули и DB защищены server-only. Схемы входа остаются чистыми и тестируемыми.
- OpenAPI генерируется из действующих request validators, содержит матрицы ролей/владения и примеры. Полные response DTO пока не выделены, оболочка описана без ложных гарантий.
- Миграция `20261025160000_database_boundaries` добавляет индексы, ссылку чек-листа на версию условий, единственный selected-отклик и дополнительные CHECK. Таблицы/колонки не переименованы, прикладные строки не переписываются.

Резервные копии: `.local/backups/2026-10-25T15-38-00.669Z-34a0e9` и `.local/backups/2026-10-25T15-38-04.830Z-e1fa8c`. Значения секретов и содержимое пользовательских записей в отчёт не включены. [Сводка сравнения](../../11_Reports/Audit_Reports/api-database-preservation.json).

## Решения и ограничения

Решение о совместимости и доменных границах: [ADR-002](../../11_Reports/Decisions/ADR-002-api-database-boundaries.md). Структура БД: [database.md](../database.md), API: [контракт](../api/README.md).

Postman CLI в окружении не найден; использованы локальный OpenAPI и существующие Vitest/Playwright/SQL-инструменты. Публикации в workspace и внешние сервисы не выполнялись. Новые зависимости не добавлялись. Производственный хостинг, SMTP-доставка и производительность на большом объёме этим локальным прогоном не проверялись. PostgreSQL RLS не внедрялась; проверки принадлежности данных выполняются серверным приложением.

Q10/Q11 остаются частичными/следующими: просмотры, зрелые повторы, затраты и фоновые напоминания не добавлены этой организацией. Агрегатор пока не реализован. Следующее рабочее действие — Q10 по [progress.md](../../01_Project_Overview/Roadmap/progress.md).
