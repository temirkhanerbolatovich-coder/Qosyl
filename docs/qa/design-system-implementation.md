# Внедрение дизайн-системы Qosyl

Этап начат 26.10.2026, завершён 27.10.2026. Основание — отдельный пользовательский запрос Design System & UI/UX после инфраструктурного аудита, затем обязательный исходный логотип и подтверждение необходимости светлой темы. Ограничение первого этапа «не менять UI» к этому запросу не относится; бизнес-логика защищена по-прежнему.

## Изменения

Внедрены Deep Blue + Teal, Light/Dark/System, локальные Manrope/Inter и пользовательский логотип. Канонические токены — src/lib/design-tokens.json, генерируемый CSS — src/app/design-tokens.css. Существующие классы/компоненты сохранены и используют semantic variables вместо прежних разрозненных HEX. Новые правила в design-system.css применены после базовых стилей ко всем существующим страницам.

Обновлены общие controls, focus/error/disabled/hover состояния, радиусы, типографика, сетка и мобильное меню. Фильтры на узкой ширине идут одной колонкой, controls около 44 px; карточки получили более читаемые условия, явную ссылку и настоящий статус. StatusBadge сохраняет доменную подпись и добавляет Lucide-иконку. Галлюцинированные KPI/отзывы/партнёры не добавлялись.

На главной основной CTA «Найти проект», второй «Разместить задачу», компактный процесс и честный FAQ. Реальные проекты по структуре идут до внешних возможностей. У каталога возможностей убран повтор вводных заголовков; карточки показывают дату публикации либо прямо сообщают, что она неизвестна. Одобрение, срок актуальности, происхождение и правила публикации сохранены.

## Темы, шрифты и бренд

Выбор сохраняется в localStorage, System отслеживает prefers-color-scheme; storage events синхронизируют вкладки. Валидирующий статический script выполняется в head до основного содержимого. CSS color-scheme согласует native controls; системная тема имеет fallback без JS. При блокировке storage ручной выбор работает до ухода со страницы, но не обещает невозможную персистентность. CSP не ослаблялась.

Палитра проверена в реальном браузере, а не только по исходным HEX. В первой версии action text на tinted surfaces дал 4.21:1 light и 4.38:1 dark: добавлен отдельный action-text и новые контрастные пары. Эти ошибки исправлены без отключения axe.

Manrope/Inter получены из Google Fonts, лицензии OFL включены, TTF преобразованы в WOFF2 (404064 байта суммарно). В браузере нет запросов к Google Fonts. Русская кириллица есть в обоих; Kazakh glyph fallback для Manrope явно идёт в Inter. Для конвертации в существующий изолированный Python-venv добавлены fontTools 4.67.0, Brotli 1.2.1, zopfli 0.4.3; npm/runtime dependencies не добавлены. [Метаданные шрифтов](../../outputs/ui-quality/fonts.json).

`public/brand/qosyl-logo.jpg` — побайтовая копия файла пользователя. Логотип используется в шапке, подвале и metadata icon; старый буквенный знак не отображается. Цвета/композиция оригинала не перерисовывались. Белый фон JPG сохранён и в тёмной теме. [Хеш и границы изменений](../../outputs/ui-quality/design-preservation.json).

## Исправления в процессе

Первый большой UI-прогон получил 36 отказов входа из-за частых повторных логинов: действующий лимит 10/min не ослаблялся. Тесты теперь переиспользуют три приватные demo-сессии, привязанные к уникальной тестовой БД, без доступа к пользовательской сессии Meta. Cookies находятся только в игнорируемой .local; их нельзя публиковать.

Функциональные прогоны выявили два устаревших селектора: бренд больше не имеет сокращённого aria-label, а CTA «Найти проект» существует и в nav, и в hero. Тесты проверяют новое полное доступное имя и ограничивают CTA областью hero. Assertions бизнес-сценариев не удалены. Исторические 13/18 успешных тестов с остановкой serial suite не выдавались за полный успех; итоговый прогон выполнен целиком.

## Почему без второго UI-кита

Существующие Tailwind/native CSS и компоненты покрывают задачу. shadcn CLI мог бы заменить CSS/config и потребовал бы миграции рабочих контролов; он не запускался. Не добавлялись несуществующие Dialog/Tooltip-сценарии, Storybook, Motion и таблицы-виджеты ради формального списка компонентов. При появлении сложного нового widget выбор primitives проверяется отдельно. [ADR-010](../../11_Reports/Decisions/ADR-010-brand-themes.md).

## Ограничения

Браузерная автоматизация выполнялась в Chromium на локальном production build. Реальные iOS/Android, Safari/Firefox, screen reader, физическая экранная клавиатура и все рабочие состояния в обеих темах отдельно не сертифицированы. Проверки включают узкую ширину 320, но это не заменяет фактическую проверку browser zoom 200%. Field CWV, Lighthouse и исследование с реальными студентами не проводились. Неблокирующее существующее предупреждение pg о concurrent query в тестах не исправлялось вне UI-объёма.

Никаких внешних публикаций, платных сервисов, cloud deployment, изменений ролей/валидации/схемы БД не выполнялось. Локальный сервер восстановлен на localhost:3000. Кодовые токены/стандарты и AGENTS обновлены; первоначальная спецификация сохранена как исторический draft.

## Воспроизведение и артефакты

```powershell
npm run ui:tokens
node scripts/generate-design-tokens.mjs --check
npm run test:ui
npm run test:e2e
```

Для сборки использовать npm run build при остановленном локальном сервере и без параллельного E2E, использующего ту же .next. Стандартный UI runner использует порт 3100, уникальную локальную E2E-БД и выключенный Threads provider.
