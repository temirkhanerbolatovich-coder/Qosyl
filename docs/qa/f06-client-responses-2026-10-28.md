# F06: безопасные ответы клиентов

## Что изменено

Конечный пакет из пяти клиентов из [инвентаризации](../localization-error-inventory.md): закрытые файлы, избранное, редактор материала, закрытая очередь и реестр/карточка лида.

- Новый небольшой `client-data-response.ts` проверяет текущий строгий `{ data }`-контракт через `safeParse`. Некорректные JSON, поля и сеть дают стабильное сообщение RU/KK без сырого Zod, `SyntaxError` или `Failed to fetch`. Неизвестная строковая причина собственного API сохраняется для существующего механизма показа оригинала. Объект в поле `error` не превращается в `[object Object]`.
- Контент и лиды теперь используют уже существующие схемы чтения/команд. Материал без последней редакции отвергается до обращения к `revisions[0]`. Серверные API, статусы, маршруты, права и правила публикации не менялись.
- Неподтверждённый ответ команды сообщает об отсутствии подтверждения и предлагает обновить данные. Только успешная проверка ответа команды позволяет затем сообщить, что действие выполнено, но последующее чтение не удалось. Автоматического повтора команд нет.
- Формы создания источника/лида, редакторское решение и действие по лиду не очищаются из-за неудачного обновления. Уведомление об успехе появляется после обновления. Обновление карточки/материала доступно отдельной кнопкой, включая ошибку начального чтения. Оно не отправляет команду.
- Файлы используют безопасную проверку схемы с прежним механизмом статусов/скрытия приватных данных. Неудачная команда или обновление не сбрасывают выбранный файл. Избранное уже имело безопасную проверку схем; уточнён тип серверного сообщения и расширены отрицательные сценарии.

Выбран простой клиентский механизм поверх текущих контрактов, без зависимостей и замены общего серверного валидатора. Значимого архитектурного решения нет; отдельный ADR не нужен.

## Проверки

Unit: **456/456**, 42 файла, включая пять новых проверок границ схемы/JSON/сети/строкового error и перевода. Typecheck, ESLint, OpenAPI `api:check`, production build и `git diff --check` прошли. API-контракт не изменился. CLI Postman отсутствует; использованы существующие контракты, Vitest и Playwright проекта, без создания внешнего workspace.

Целевой dev-прогон шести новых административных сценариев прошёл **6/6** после исправления тестовой подготовки. Отдельно прошли два сценария ошибок избранного и расширенный полный сценарий файлов. Первый прогон административных проверок использовал неправильный селектор `alert` для существующего `LoadState`; следующий повтор обнаружил неуникальные названия синтетических записей в повторно используемой dev-базе. Селекторы исправлены, имена фикстур стали уникальными. Проверки не ослаблены.

Проверены состояния на `/admin`, `/opportunities/saved`, `/work/[id]` под администратором/студентом; реальный файловый сценарий включает заказчика. Сетевые сбои и испорченные ответы перехватываются только в тестовом браузере. Подготовка записей и основной файловый путь используют реальные API изолированной БД. Перехваченные успешные ответы не доказывают реальную запись: они проверяют переход клиента между состояниями. Финальный общий production-прогон: **73/73** на новой управляемой изолированной БД, без retries и пропусков. Он повторно включает все новые сценарии, реальную редакционную публикацию/отзыв, приватный лид с согласием и файловый рабочий процесс.

Редактор в KK: 375/768/1440/1920 px, без горизонтального переполнения и serious/critical axe-нарушений внутри `main`. Снимки всей страницы и панели: `.local/f06-client-response-errors/`. Просмотрены четыре ширины панели; полные страницы дополнительно просмотрены на 375/1440. Синтетический исходный текст в RU намеренно не переводится. Снимки — наблюдения, не утверждённые эталоны дизайна. Проверки реального файла дополнительно включают светлую/тёмную тему на четырёх ширинах.

## Сохранность и ограничения

Приложение пересобрано и возвращено на локальный порт 3000 как web-only; отдельные фоновые процессы основной базы не запускались. Предыдущая сборка сохранена в `.local/previous-build-f06-client-responses`. Миграции и изменение основной БД этому пакету не нужны; записи тестов ограничены изолированными базами.

Полный строгий `test:ui` этим пакетом не запускался. Прочие динамические/refine-ошибки, редактура KK носителем, диктор, native zoom и разные браузеры остаются открытыми. Явное успешное обновление изменившейся версии карточки может заново заполнить её форму актуальными данными; это не сохранение черновика после перезагрузки страницы. Неизвестные строковые ошибки сохраняются согласно существующей политике, а не угадываются переводчиком.

Следующий пакет: фиксированная часть специальных правил и динамических ошибок — даты, HTTPS, закрытые ссылки, согласия и причины ролей/модерации.

В конце общего прогона `pg` выдал DeprecationWarning о вызове `client.query()` при уже выполняющемся запросе на том же клиенте. Это не провал проверки; источник этим пакетом не локализован. Разобрать отдельно до перехода на pg 9.
