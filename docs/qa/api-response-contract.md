# Приёмка точного контракта ответов API

Дата: 25.10.2026. Этап «Довести описание API» завершён.

## Результат

Общие wire-схемы: `src/contracts/api-entities.ts` и `api-responses.ts`. Они описывают сериализованный JSON, включая ISO-строки дат, nullability, обязательные поля, статусы и вложенные связи. Объекты строгие: неожиданное поле приводит к ошибке проверки, а не молча удаляется. Версии условий имеют отдельную схему исторического снимка без проверки «дата должна быть в будущем». Метаданные событий описывают используемые поля истории.

| Область | Покрытие |
|---|---|
| Чтение биржи | catalog, project, dashboard, portfolio, work, applications, admin, pilotMetrics |
| Команды | Все 27 action из mutationSchemas, с точным результатом каждой команды |
| Профиль | GET собственного профиля и POST сохранения |
| Operational health | Отдельные 200 ok и 503 unavailable |
| Ошибки | error, стабильный code, необязательное fields |

В OpenAPI удалён неопределённый ApiSuccess.data. Именованные схемы и x-view-response/x-action-response связывают селектор с результатом; anyOf допускает совпадающие структуры, не добавляя discriminator в реальный HTTP-ответ. Better Auth сохраняет собственный контракт провайдера.

`ViewData<V>` и `CommandData<A>` выводятся через Zod. `useData` принимает известный раздел и выводит его тип; `useAction.run` возвращает результат выбранной команды. Типы общих карточек отделены от точных endpoint-типов. Удалены устаревшие запасные обращения к snapshot/completed/resultLinks/timestamp/message/title там, где сервер всегда возвращает snapshotJson/done/links/createdAt/text. Содержимое форм, роли и порядок бизнес-действий не изменены. Новая форма не загружает неиспользуемый dashboard; её запрос отключён до появления ID проекта.

## Проверки

- `npm test`: **93/93**, 13 файлов. Включает 14 проверок response-схем и 9 проверок OpenAPI, отрицательные формы, лишние приватные/auth-поля, даты и nullable-значения.
- `npm run test:e2e`: **17/17**, реальное приложение, Chromium и отдельная PostgreSQL. Helpers проверяют JSON-ответы каждой команды/раздела общими схемами. Итоговый тест сравнивает покрытый набор со всеми 27 командами и 8 разделами.
- Проверены непустой собственный отклик, внешняя работа в профиле/откликах, оба профиля, версии условий до/после согласования, сдачи/правки, отзывы, портфолио, спор, отмена и уведомление адресата.
- Для project общий union не подменяет проверку доступа: гостевой и неавторский ответ дополнительно проверяются публичной схемой, собственный — схемой автора. Catalog/admin не допускают приватный адрес/контакт. POST и ошибки проверяются отдельно от публичного чтения.
- `npm run build`, `npm run typecheck`, `npm run lint`, `npm run api:check`, `git diff --check`: пройдены. При первичной проверке lint указал неиспользуемый импорт после удаления старого типа; импорт убран.

Фикстуры E2E относятся только к student_marketplace_e2e. Основная схема БД, миграции и пользовательские данные этим этапом не менялись. Никаких новых зависимостей или внешних публикаций не добавлено.

## Границы результата

В production ответы дополнительно не парсятся и не переписываются Zod: типы используются при разработке, схемы — для генерации OpenAPI и проверки HTTP в тестах. Строгая форма сама по себе не является авторизацией; права по-прежнему проверяет сервер. Внешний SMTP, production-хостинг и производительность больших ответов этим этапом не проверялись. Старый отчёт api-database-boundaries.md сохраняет результаты предыдущего этапа; его упоминание незавершённых response DTO теперь историческое.
