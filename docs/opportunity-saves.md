# Избранные возможности и сохранённые поиски

F04, 27.10.2026. Активный пользователь сохраняет интересные возможности и применённые условия поиска между сеансами. Завершённый профиль/роль студента или заказчика не требуются: функция доступна и на этапе onboarding. Данные находятся в PostgreSQL и видны только владельцу аккаунта.

## Пользовательский путь

В `/opportunities` авторизованный пользователь нажимает «В избранное» у опубликованной карточки. Состояние меняется после подтверждения сервера. Повторный запрос не создаёт новую запись. В форме «Сохранить текущий поиск» указывается название; сохраняются применённые условия, а не несохранённый ввод в форме фильтров.

Ссылка «Моё избранное и поиски» ведёт на `/opportunities/saved`; она также доступна из кабинета. Там можно открыть поиск, удалить его или убрать материал из избранного. Открытие поиска восстанавливает видимые фильтры, URL и актуальную выдачу; начинается первая страница. Название не участвует в идентичности поиска: повтор тех же критериев сохраняет исходное название, не переименовывает запись.

Гостю показывается ссылка входа. Если сессия истекла, личные данные скрываются и предлагается войти снова. Сетевой сбой не изображается успешным сохранением; если POST подтверждён, а последующее чтение не удалось, интерфейс сообщает это и предлагает обновить список.

## Видимость материалов

Избранное ссылается на постоянный ContentItem, но отображает только текущую одобренную редакцию. Применяются те же условия, что в публичном каталоге: включённый модуль и источник, status=published, будущий expiresAt и approvedRevisionId. Если материал скрыт, отозван или истёк, API возвращает `post: null` без заголовка, текста и ссылки непубличной версии. Такая запись остаётся удаляемой. После повторного одобрения может снова показываться актуальная карточка.

Клиент скрывает заведомо истёкшую карточку по таймеру. Обновление при возвращении вкладки и каждые 15 секунд получает текущую видимость. Это не гарантирует мгновенного удаления ранее увиденного текста с экрана во всех браузерных вкладках. Данные позднего ответа другого аккаунта не подставляются в текущий интерфейс.

## Хранение и ограничения

- OpportunityFavorite: уникальная пара userId/itemId, createdAt; до 100 записей на аккаунт.
- SavedOpportunitySearch: имя до 80 символов, q/category/specialty/geography, SHA256 нормализованных критериев; до 20 поисков.
- Нормализация: Unicode NFKC, trim, свёртка пробелов и регистр RU/KZ. Ограничения длины повторно проверяются после преобразования Unicode.
- page и limit не являются критериями, userId не принимается в командах. Ссылки поиска всегда локальные и строятся через URLSearchParams.
- Сохранения и квоты сериализуются блокировкой строки пользователя. Повторное сохранение и удаление безопасны; лимит не обходится параллельными запросами.
- Удаление выполняется по ID только среди записей текущего пользователя. Чужой/отсутствующий ID даёт тот же успешный no-op; существование чужой записи не раскрывается.
- Строки личных сохранений удаляемые; редакционные версии и журнал контента не затрагиваются. FK пользователя CASCADE применяется только при разрешённом реальном удалении User; механизма удаления аккаунта этот этап не добавляет. FK ContentItem RESTRICT сохраняет ссылочную целостность.

Новые таблицы не используют RLS; изоляция проверяется в серверном коде и тестах. Роли, модерация и согласия биржи не меняются. Пользовательские строки поиска не добавляются в логи.

## API

`GET /api/opportunities/saved` возвращает `{data:{favorites,searches}}`, private/no-store. В favorites: id, itemId, createdAt, post или null. В searches: id, name, createdAt, filters; после продолжения F04 также notificationFrequency и nextNotificationAt.

`POST` требует текущую сессию, same-origin JSON и тело до 8192 байт. Команды:

```json
{"action":"saveFavorite","itemId":"public-content-id"}
{"action":"removeFavorite","favoriteId":"own-favorite-id"}
{"action":"saveSearch","name":"Медицина","filters":{"q":"стажировка","geography":"","specialty":"health"}}
{"action":"removeSearch","searchId":"own-search-id"}
```

Ответ `{data:{saved:true}}`. Ошибки следуют действующему envelope: 401 — нет сессии, 403 — недоступный аккаунт/Origin, 400 — поля/JSON, 404 — новый материал недоступен, 409 — квота/конфликт, 413 — размер. Строгие схемы и OpenAPI генерируются из текущего контракта.

## Развёртывание и проверка

Миграция `20261027010000_opportunity_saves` добавляет две таблицы с UTC defaults, FK, индексами и CHECK значений поиска. Новых npm-зависимостей нет. На основной БД сначала выполнить проверенный backup/restore, затем `npm run db:migrate`; клиент Prisma генерируется при сборке. Для приложения с отдельной DML-ролью проверить права на новые таблицы в процедуре production-миграции.

Команды: `npm test`, `npm run test:content`, `npm run test:e2e`, `npm run lint`, `npm run typecheck`, `npm run api:check`, `npm run build`. Интеграционные и браузерные проверки используют изолированные БД.

Последующее продолжение F04 добавляет [добровольные уведомления сохранённых поисков внутри Qosyl](opportunity-search-notifications.md). По умолчанию выключены. Внешних каналов нет; первоначальная приёмка выше относится к избранному и поискам.
