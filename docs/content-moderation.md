# Модерация и лента возможностей

Продолжение от 26.10.2026: [HTML/RSS-сбор и общий поиск возможностей](opportunity-discovery.md). Добавлены HTML-источники, категории грантов/стипендий/обучения и текстовые фильтры; ниже сохранено описание предыдущего этапа.

Этап 4 продолжает [закрытый сбор](content-intake.md). Администратор проверяет конкретную неизменяемую редакцию и явно решает, можно ли показать её на главной. Внешний материал остаётся отдельным от заказа Project. Импорт не публикует материал и не отправляет сообщения людям.

## Работа редактора

1. Открыть admin → «Сбор возможностей». Фильтр «Раздел материалов» показывает очередь, опубликованное, отклонённое, архив и отозванное; «Все материалы» сохраняет прежний общий просмотр.
2. Нажать «Проверить и открыть историю». Проверить оригинал, аудиторию, условия источника, географию и даты. Оценка релевантности — результат правил, не вероятность достоверности и не подтверждение права публикации.
3. При необходимости раскрыть «Исправить материал перед публикацией». Сохранить собственный краткий анонс, категорию, язык, географию, подтверждённые даты и причину изменения. Пустая дата остаётся неизвестной. Создаётся новая редакция; история не перезаписывается.
4. Выбрать решение и обосновать его минимум десятью символами. Для публикации указать срок актуальности. Указанное в форме начальное значение — предложение редактору, оно не становится дедлайном мероприятия автоматически.
5. Проверить карточку в разделе «Возможности и события» под основными действиями главной. Ссылка ведёт на оригинал, условия участия уточняются у организатора.

Публиковать можно только `pending_review`, когда модуль и источник включены. Сервер проверяет, что редактор отправил текущие `expectedRevisionId` и `expectedUpdatedAt`; устаревшая форма получает 409 и требует обновления. Новая редакция старого материала без сохранённого URL обязательна перед его первой публикацией: историческая ссылка не угадывается.

Редакционное исправление возможно и при выключенном модуле. Для `rejected`, `archived` и `withdrawn` сначала нужно явное решение «Вернуть на проверку». Автоматический импорт эти статусы не возвращает. Архив, отклонение и отзыв доступны при выключенном модуле, поэтому можно убрать карточку до следующего включения.

## Редакции и повторный импорт

ContentRevision сохраняет URL, поля содержания, номер и происхождение `import`, `manual`, `editorial` или `legacy`. Снимок защищён append-only триггером. Item содержит отдельные `approvedRevisionId`, `approvedAt`, `expiresAt`; публичная проекция читает только этот снимок.

Порядок при изменениях:

- Повтор текущего внешнего содержания не создаёт редакцию.
- После редакторского исправления неизменённый внешний материал сравнивается с последним внешним снимком. Он не отменяет редактуру и не снимает её публикацию.
- Реальное изменение источника создаёт новую редакцию, переводит Item в `pending_review` и скрывает его. Старое одобрение и редакторский текст сохраняются в истории, но не дают разрешения новой версии.
- Явный возврат источника A→B→A остаётся последовательностью из трёх наблюдавшихся редакций, а не потерей последнего изменения.
- Отозванная/архивная/отклонённая запись служит отметкой исключения: импорт не создаёт её заново. Вернуть её может человек с причиной и последующей новой проверкой.

История читается по 20 редакций на страницу, по убыванию номера. Два выбранных снимка показаны рядом для сравнения текста, URL, категории, географии, языка и дат. Текущая редакция для решения всегда читается отдельно от страницы истории. Журнал показывает последние 50 действий, включая ID автора и редакции; это внутренние данные администратора.

## Актуальность и выключение

При публикации явный срок должен быть в будущем и не дальше 90 дней. Более ранние известные deadline или eventDate сокращают его; уже прошедшая дата запрещает публикацию. У новости без дедлайна редактор всё равно задаёт срок свежести. Публичный API фильтрует `expiresAt > now` независимо от worker.

Контентный worker архивирует до 100 истёкших опубликованных материалов за проход и пишет системный `content_expired` без поддельного администратора. Это выполняется даже при выключенном сборе. При остановленном компьютере архивный статус обновится после запуска, но просроченный материал уже исключён из публичной выдачи.

Выключение модуля скрывает все карточки и запрещает новые внешние обращения; отключённый источник также исключается из ленты. Включение источника может вернуть его прежнюю, ещё актуальную одобренную карточку; для постоянного снятия используют отзыв/архив. Уже начатый сетевой запрос не отменяется, однако результат не записывается, если флаг выключен перед фиксацией.

## API и безопасность

| Маршрут                                               | Доступ и результат                                                                                                                                                                                |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/content/posts?limit=6`                      | Гостевой; limit 1–6, стабильный порядок approvedAt/id по убыванию. Только одобренные, актуальные материалы включённых источников при включённом модуле. Пустота/выключение → `{data:{posts:[]}}`. |
| `GET /api/admin/content?page=1&status=pending_review` | Admin; status необязателен. По 20 материалов; total относится к выбранному статусу. Настройки, источники и последние runs сохраняют прежнюю форму.                                                |
| `GET /api/admin/content/{id}?page=1`                  | Admin; последняя редакция, внутренний источник, история по 20, historyTotal, последние 50 audit.                                                                                                  |
| `POST /api/admin/content` action=`editContent`        | Admin; itemId, expectedRevisionId, expectedUpdatedAt, reason и поля новой редакции. Возвращает `{data:{saved:true}}`.                                                                             |
| `POST /api/admin/content` action=`reviewContent`      | Admin; те же идентификаторы/проверка версии, reason, decision publish/reject/archive/withdraw/reopen. Для publish обязателен expiresAt. Возвращает `{data:{saved:true}}`.                         |

Прежние пять действий источников/сбора сохранены: всего семь. POST повторно проверяет активность аккаунта и роль в Serializable-транзакции, требует точный Origin и JSON до 32768 байт, вне локального режима — подтверждённый email. Изменение состояния и аудит фиксируются вместе; конкурентные изменения возвращают 409. БД дополнительно запрещает связь одобрения/аудита с редакцией другого материала, публикацию без одобрения, неполные сроки и редакционные решения без автора/основания.

Публичный ответ содержит только id, title, summary, category, geography, language, url, sourceName, publishedAt, approvedAt, expiresAt, deadline, eventDate. В нём нет внутренних заметок о правах, идентификаторов автора/источника, hash, externalId, истории и run log. Выдача не обращается к внешним источникам.

Ответы используют private/no-store, общие коды ошибок и точные схемы [OpenAPI](api/README.md). Нет CDN/server-кэша контента. Открытая главная повторяет чтение каждые 15 секунд и при фокусе; локально известный срок истечения проверяется каждую секунду. Более старый ответ не заменяет более новый. При ошибке блок скрывается; CTA, каталог, вход и работа заказа не зависят от контентного запроса. Серверная выдача скрывает отзыв сразу для следующих запросов; уже открытая вкладка увидит решение при ближайшем обновлении.

## Проверка и ограничения

На подготовленной локальной E2E-БД: `npm run test:content`, `npm run test:db`; затем `npm test`, `npm run api:check`, `npm run typecheck`, `npm run lint`, `npm run build`, `npm run test:e2e`. Интеграционные файлы контента запускаются последовательно, потому что проверяют общий флаг модуля. Настройки восстанавливаются, свои источники выключаются, неизменяемая тестовая история сохраняется.

Сбор настоящего RSS проверен на этапе 3; этап 4 проверяет редакционные решения на синтетических материалах в E2E, без публикации настоящих новостей в основной БД. Postman CLI отсутствует, поэтому проверка HTTP выполнена Playwright и нативными TLS-fixture, а не Postman simulation. [Фактическая приёмка](qa/content-moderation.md), [ADR-005](../11_Reports/Decisions/ADR-005-content-publication.md).

Нет общей дедупликации разных источников, редактирования источников, credentials, очередей социальных адаптеров, сообщений, бизнес-лидов и retention-политики. В сравнении снимки показаны рядом, без посимвольной подсветки. Публичная выдача ограничена шестью карточками, отдельная страница каталога возможностей и пагинация пока не нужны. Реальные источники пилота и их право использования проверяет редактор. Локальный запуск не означает размещение в интернете или подтверждённый спрос.
