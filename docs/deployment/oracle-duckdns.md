## Автоматическое обновление DNS — 01.11.2026

Токен общего аккаунта DuckDNS перевыпущен; новые значения защищённо установлены на серверах Qosyl и Qutty Qonaq. Для Qosyl работает отдельный `qosyl-duckdns.timer`, который примерно каждые пять минут запускает `qosyl-duckdns.service`. Служба `/usr/local/sbin/qosyl-duckdns-update` обновляет только `qosyl.duckdns.org`, определяя IPv4 по исходящему запросу; после смены IP необходимы успешный запуск и истечение DNS-кэша. Таймер Qutty Qonaq обновляет только её адрес с другой машины.

Ключ Qosyl хранится в `/etc/qosyl/duckdns-token` с правами root:root 600; это общий токен аккаунта, поэтому он позволяет менять и остальные его домены. Не включайте его в логи, репозиторий или сообщения. При следующем перевыпуске нужно одновременно обновить оба сервера. Прежняя отдельная настройка `assetguard-duckdns` относится к другому имени и осталась отключённой; её содержимое не менялось.

После перевыпуска проверены успешный запуск обеих служб, включённые таймеры, независимые DNS-записи, HTTPS `/api/health` обоих сайтов и работа TimScheduleBot. Реальная смена IP и восстановление удалённой машины не проверялись. Если VM полностью недоступна, обновление DNS на ней не выполняется; при переносе нужно восстановить настройки или изменить запись вручную. Бесплатный DNS и виртуальная машина не гарантируют постоянной доступности.

Восстановление после безопасного размещения токена на сервере:

```sh
sudo install -d -o root -g root -m 700 /etc/qosyl
sudo install -o root -g root -m 700 deploy/oracle/qosyl-duckdns-update.py /usr/local/sbin/qosyl-duckdns-update
sudo install -o root -g root -m 644 deploy/oracle/qosyl-duckdns.service deploy/oracle/qosyl-duckdns.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl start qosyl-duckdns.service
sudo systemctl enable --now qosyl-duckdns.timer
systemctl show qosyl-duckdns.service -p Result -p ExecMainStatus
systemctl list-timers qosyl-duckdns.timer --no-pager
```

Файл `deploy/oracle/duckdns-update.mjs`, описанный ниже, остаётся отдельным ручным инструментом со статическим IPv4 и не является запущенной службой автообновления.

### Резервные копии

`deploy/oracle/backup.sh` установлен как `/usr/local/sbin/qosyl-backup` (700).
`qosyl-backup.timer` запускает service ежедневно в 02:30 UTC со случайной задержкой
до 15 минут. Копии PostgreSQL custom format и SHA256 хранятся в
`/var/backups/qosyl` (700), файлы 600. Retention 14 дней касается только файлов
`database-*.dump*` внутри этого каталога после успешного создания новой копии.

Первый backup и SHA256 проверены, pg_restore успешно выполнен в отдельную
временную базу: восстановлены 40 таблиц и 15 миграций; временная база удалена.
Проверка не меняла рабочую БД. Копия содержит вложения, поскольку они хранятся
в PostgreSQL. Секреты и сертификаты в этот backup не входят. Копии на том же диске
не заменяют внешнее резервирование.

```sh
sudo systemctl start qosyl-backup.service
sudo systemctl show qosyl-backup.service -p Result
sudo systemctl list-timers qosyl-backup.timer
```

## Безопасная конфигурация

Для упаковки текущих исходников на Windows: `powershell -NoProfile -File scripts/package-pilot.ps1`. Скрипт собирает явно указанные исходные каталоги и конфигурацию в новый каталог `.local/pilot-package/<timestamp>`, проверяет список архива и записывает SHA256. Реальные env-файлы, `.local`, Git, зависимости, исследования и архивы старых проектов не включаются; включены только два env-шаблона. Это пакет исходников, не резервная копия production-БД и не готовый Linux-образ. Перед передачей сверить `archive-entries.txt`, на сервере сверить SHA256.

1. На новой VM выбрать отдельный каталог, например `/opt/student-marketplace`, и доставить туда исходники без `.env`, `.local`, `research`, `node_modules` и чужих архивов. Архивы старых проектов содержат секреты и НЕ являются частью нового приложения.
2. Скопировать `deploy/oracle/.env.production.example` в `.env.production` того же каталога. Права600, владелец — оператор. Пример содержит пустые обязательные поля и намеренно не готов к запуску.
3. `OWNER_DB_PASSWORD` и `APP_DB_PASSWORD` — разные случайные hex-строки, минимум32байта каждая. `BETTER_AUTH_SECRET` — отдельный случайный секрет. Не передавать секреты в аргументах SSH/Docker-команд и не печатать env.
4. Заполнить реальные SMTP HOST/PORT/USER/PASSWORD/FROM. Допускаются465/TLS и587/STARTTLS с проверкой сертификата. Адрес сайта DuckDNS не создает почтовый ящик и не подтверждает право отправки email.
5. DNS-запись настроена через dashboard DuckDNS: для основного запуска токен не нужен. Если оператор включает профиль `dynamic-dns`, `DUCKDNS_TOKEN` хранится только в защищенном env-файле. `DUCKDNS_IPV4` — фактический публичный IPv4 выбранной VM.

docker compose --env-file deploy/oracle/.env.production -f deploy/oracle/compose.yml up -d --build

Демо seed в production запрещен. Первый администратор: обычная регистрация с подтверждением email и серверная команда `npm run admin -- <email>` в контейнере. Создание админа через публичную форму невозможно.

## DuckDNS updater

Сервис выключен по умолчанию. После регистрации поддомена и заполнения трех переменных `DUCKDNS_*` его можно включить отдельно:

```sh
docker compose --env-file deploy/oracle/.env.production -f deploy/oracle/compose.yml --profile dynamic-dns up -d dns
```

Официальный endpoint фиксирован в коде; произвольные URL, несколько доменов и локальные IP отвергаются. По умолчанию CLI только проверяет конфигурацию; `--apply` выполняет HTTPS-запрос, `--loop` повторяет каждые5минут. Успех — только HTTP200 с телом `OK`; `KO`, редирект, timeout и ошибка не считаются успехом. URL с токеном и исключение fetch не печатаются. При смене публичного IP VM нужно обновить `DUCKDNS_IPV4`; updater не угадывает адрес другого компьютера.

Unit-тесты проверяют построение запроса и разбор ответа **без сети**. Реальный update не выполнялся, пока не подтвержден новый IP и владение выбранным поддоменом.

## Что еще требуется

Настоящий SMTP, получение TLS, Linux image build/run, проверка least-privilege роли, резервное копирование и восстановление новой PostgreSQL, внешний smoke с телефона, оператор поддержки и юридические тексты. До этого закрытый пилот не объявляется production-ready. Не использовать `docker compose down -v`, prune или очистку чужих томов.
