# Уведомления о новых возможностях

Системный текст новой подборки использует язык, сохранённый получателем в кабинете; по умолчанию RU. Критерии поиска и исходное содержимое материалов не переводятся. Для работы необходима миграция `20261028010000_notification_language`.

F04, 27.10.2026. Сохранённый поиск может проверять новые совпадения и создавать уведомление в личном кабинете Qosyl. Новых зависимостей и внешних сервисов нет. Все поиски, включая существующие, по умолчанию выключены.

## Использование

В `/opportunities/saved` выберите у поиска «Раз в 24 часа» или «Раз в 7 дней» и нажмите «Сохранить уведомления». До подтверждения форма не меняет серверную настройку. Черновой выбор сохраняется при автоматическом обновлении списка; ошибка не изображается успешным сохранением. Данные принадлежат только текущему активному аккаунту; завершение профиля не требуется.

Первый проход назначается через 24 часа / 7 дней после включения. Далее интервал отсчитывается от фактического прохода; это длительности, а не календарное утро или конкретный день недели. Повтор той же частоты не переносит срок. Изменение включённой частоты назначает новый срок, сохраняя исходную границу поиска и учтённые материалы.

«Выключены» с подтверждением прекращает будущие уведомления. Удаление поиска также прекращает их и удаляет его журнал совпадений. Уже полученные уведомления остаются в кабинете по существующим правилам неизменяемой истории. В их внутренних ссылках сохраняются критерии поиска; удаление поиска не удаляет эту историю. Сроки хранения и удаление аккаунта требуют отдельной работы F07.

Письма, Telegram, browser push и сообщения организаторам не отправляются. Включённый фоновой процесс сам по себе никого не подписывает.

## Что считается новым

- Используются те же SQL-предикаты q/category/geography/specialty, что и в публичном поиске, включая RU/KZ и словарь специальностей. Семантического AI matching нет.
- Материал должен быть опубликован после включения, оставаться актуальным в момент проверки, иметь включённый источник и одобренную редакцию с URL. Неодобренный свежий draft не участвует. Будущая дата одобрения не участвует.
- Уже опубликованный при включении каталог не рассылается. Повторное одобрение старого материала после включения может впервые попасть в уведомление. После первого учёта один ContentItem больше не отправляется этому поиску, в том числе после редактирования/переодобрения.
- Повторное включение начинает новую временную границу: публикации периода отключения не догоняются. Журнал ранее учтённых ID сохраняется до удаления поиска.
- Для пересекающихся поисков возможны отдельные уведомления: идентичность совпадения задана парой searchId/itemId.

За период учитывается не больше 50 совпадений, начиная с наиболее раннего одобрения. Остальные не помечаются обработанными и могут попасть в следующий период, если останутся публичными и актуальными. Материал, истёкший до следующей проверки, намеренно не доставляется. Поэтому недельный режим может пропустить короткие возможности. При остановленном компьютере проверки не выполняются; после запуска проверяются всё ещё доступные материалы.

Текст уведомления содержит только число новых совпадений и переход в актуальную выдачу. Заголовки, summary и внешние ссылки публикаций не копируются в неизменяемую историю: снятие публикации не оставляет там закрытый текст. Выдача по ссылке может измениться после доставки. Кабинет получает последние 30 уведомлений; раскрытие показывает весь загруженный список.

## Хранение и транзакции

Миграция `20261027020000_opportunity_search_notifications` добавляет частоту, notificationSince и nextNotificationAt в SavedOpportunitySearch и таблицу OpportunitySearchMatch. SQL CHECK запрещает противоречивое состояние off/дат. Уникальность searchId/itemId защищает от повторов; FK поиска CASCADE, материала RESTRICT. Журнал хранит ID, без копии контента.

Настройки сериализуются существующей блокировкой User. Worker берёт transaction advisory lock `[5328723,12]`, редакционный singleton ContentModuleSettings, затем User и SavedOpportunitySearch; читает настройки заново. Одобрение/отзыв источника или материала использует тот же редакционный lock. Notification, журнал и следующая дата записываются в одной Serializable-транзакции; конфликт сериализации повторяется не более трёх раз. Незавершённый проход откатывается целиком.

Уведомление получает уникальный dedupeKey поиска и назначенного периода. Два worker или перезапуск не создают повторов. Заблокированный пользователь не получает сообщения; его дата сдвигается, чтобы он не занимал очередь постоянно. Выключенный контентный модуль не обрабатывается. Ничего не записывается в BackgroundJobRun: его контракт относится к Q11. Диагностика нового процесса — статус и счётчики в stdout/stderr без имён, запросов и секретов.

Ограничения БД дополняют проверки сервера, но RLS не добавляется. Журнал совпадений растёт вместе с доставками; отдельная политика хранения отложена до F07. Большая промышленная очередь и задержки при тысячах подписок не измерялись.

## API

Существующий `GET /api/opportunities/saved` добавляет каждому поиску notificationFrequency (`off`, `daily`, `weekly`) и nextNotificationAt (ISO UTC либо null).

Команда same-origin `POST`, cookie-сессия, JSON до 8192 байт:

```json
{"action":"setSearchNotifications","searchId":"own-search-id","frequency":"daily"}
```

Ответ `{data:{saved:true}}`. Чужой/отсутствующий поиск — одинаковый 404; неактивный аккаунт — 403, гость — 401. userId, channel, даты и произвольная частота не принимаются. Получение/удаление избранного и поисков сохраняет прежний контракт.

## Локальный запуск

После проверенного backup/restore выполнить `npm run db:migrate`, `npm run build`, `npm start`. Supervisor запускает процесс вместе с web/content/lifecycle и останавливает соседние процессы при неожиданном завершении одного из них.

```powershell
npm run worker:opportunities:once
npm run worker:opportunities
```

CLI принимает только `--once`, без изменения времени и адресата. Настройки:

| Переменная | Значение по умолчанию | Допустимо |
| --- | --- | --- |
| OPPORTUNITY_NOTIFICATIONS_ENABLED | true | true / false |
| OPPORTUNITY_NOTIFICATIONS_INTERVAL_MS | 60000 | целое 1000..86400000 |
| OPPORTUNITY_NOTIFICATIONS_BATCH_SIZE | 10 | целое 1..20 |

Глобальный false завершает worker до импорта БД. Неверная конфигурация останавливает запуск. Между проходами нет перекрытия; сбой приводит к ограниченному backoff. При остановке текущая транзакция завершается либо откатывается после прекращения процесса, следующий проход не начинается.
