## Выбор и хранение

Русский (`ru`) остаётся значением по умолчанию. Поддержаны только `ru` и `kk`; неизвестная cookie не исполняется и возвращает русский вариант. Язык устройства и Accept-Language не переопределяют явный выбор/исходный русский вариант.

Нечувствительная preference cookie `qosyl-locale` хранит только два буквенных значения, без ID пользователя, поискового запроса или роли. Path=/, Max-Age=365 дней, SameSite=Lax; HTTPS добавляет Secure. Cookie доступна JavaScript, поскольку native select меняет только представление, а не авторизацию. Если браузер запрещает cookie, текущая вкладка может продолжать использовать выбранный язык в памяти; интерфейс сообщает, что сохранение не подтверждено. Между вкладками нет обещания мгновенной синхронизации: новую cookie читает следующий серверный запрос/reload.

Root layout читает cookie через существующий Next cookies API и передаёт initialLocale клиентскому LocaleProvider. Серверная разметка начинается с выбранного html lang; нет bootstrap-подмены русского текста после загрузки страницы. Динамический layout уже существовал. Новых миграций, API endpoints и npm-зависимостей нет.

На клиенте `useI18n()` предоставляет locale, setLocale и явную пару `t(русский, қазақша)`. Вызов меняет React context, html lang и preference cookie. Он не вызывает router.refresh/reload, не меняет pathname/query и не использует ключ locale для перемонтирования форм. Заполненные поля, неподтверждённые фильтры и локальные draft должны сохраняться. Открытие следующей страницы/reload берёт тот же язык из cookie.

Это явная локализация компонентных строк. DOM не обходится для поиска/замены текста; готовые пользовательские документы и ответы API не передаются внешнему переводчику. Названия бренда и исходный логотип сохраняются.

## Язык текста и данных

html lang отражает общий выбранный язык. Основной main имеет RU fallback для пока непереведённых страниц; корни переведённых компонентов явно задают собственный lang. Исходный материал и известный русский server error получают свой lang, чтобы смена оболочки не меняла язык читаемых данных. Наличие казахской оболочки не доказывает казахский язык каждой строки пользователя.

Идентификаторы категорий/ролей/статусов, API payloads, критерии поиска, суммы, сроки и условия проекта остаются прежними. Меняются подписи и форматирование, а не доменные значения. Поиск по RU/KZ сохраняет прежние слова/нормализацию; переключение языка не переводит сам запрос и не запускает мутацию.

Форматирование даты/денег использует `ru-KZ` или `kk-KZ`; прежний timezone и сам timestamp не меняются при переключении. Казахская дата выводится явно как `ДД.ММ.ГГГГ`, со временем `ЧЧ:ММ` при необходимости. Числовые части берутся через Intl с прежним timezone: это устраняет наблюдавшийся в Chromium месяц `M11` и различие порядка частей даты между браузером и сервером. Русское форматирование сохраняется. Нельзя менять глобальный Zod locale на основании одного запроса: разные одновременные пользователи не должны влиять на ошибки друг друга. Перевод серверной валидации/почты требует отдельного request-scoped решения.

## Проверка и продолжение

Unit проверяют parse/serialization cookie, числовые KK-даты с переходом календарного дня и сохранение прежних default. E2E используют существующий изолированный Playwright server и реальные cookies: русский default/неизвестная cookie, серверный KK HTML, reload/navigation, keyboard select, сохранность query/неотправленных полей/черновика, локальные loading/empty/error. Дополнительные сценарии проверяют синтетический отказ записи cookie, сохранность черновика названия и неподтверждённой частоты поиска, исходный язык синтетической публикации и формат её срока. Визуальные проверки охватывают оба языка, light/dark и375/768/1440/1920px в оговорённом объёме. Шапка заказчика проверяется также на1600/1601px: штатное раскрывающееся меню действует до1600px, все действия остаются доступны с клавиатуры.

Тест изменения размера текста удваивает вычисленные font-size и проверяет reflow при640CSSpx. Это proxy для текстового увеличения и узкого доступного viewport, а не утверждение о настоящем browser zoom, физическом устройстве или screen reader. Наличие исполняемого файла Firefox/WebKit не считается выполнением сценариев в этих браузерах.

### F06b: авторизация и настройки профиля

Пять режимов AuthForm и onboarding/настройки исполнителя и заказчика используют существующий LocaleProvider. Ошибки хранят идентификатор/код ответа, а не уже переведённую строку: смена языка обновляет видимые сообщения без повторного POST и потери полей, согласий или внешних работ. Известные коды установленной Better Auth и точные сообщения приложения имеют явные пары RU/KK. Для профиля переводятся сводки известных code/status. Неизвестные ответы и причины модерации сохраняются в исходном виде с `lang="und"`; интерфейс помечает исходное сообщение. Глобальная локаль серверных валидаторов не меняется.

Payloads, endpoints, роли, проверки возраста/согласия, ограничения паролей и отзыв сессий сохраняются. Новых зависимостей и миграций нет. Язык встроенной браузерной валидации зависит от браузера; переведённый verify-экран не доказывает доставку SMTP или завершение подтверждения email в production. В локальном режиме подтверждение отключено, восстановление проверено через локальный mail transport. [Проверки F06b](qa/f06b-auth-profile-2026-10-27.md).

### F06c: кабинеты и рабочая область

Статические строки кабинетов, действий рабочей области и встроенных форм используют явный словарь `marketplace-copy.ts`. Он предназначен только для интерфейсного текста. Общие сообщения переводятся при отображении; неизвестные детали сервера сохраняются с пометкой исходного сообщения. Тексты Notification.text, материалов, заказов и отзывов не переписываются. Начиная с 28.10.2026 восемь шаблонов доступны на RU/KK: предпросмотр меняет язык, уже введённые поля остаются без изменений. Значения API, условия переходов, согласия, лимиты файлов и отдельный учёт оплаты сохранены. [Сценарии F06c](qa/f06c-marketplace-2026-10-27.md), [шаблоны](project-templates.md).

### F06d: публичные карточки, кандидаты и портфолио

Статические подписи и состояния используют тот же словарь. Публичный профиль сохраняет серверные запросы и проверки публикации; клиентские текстовые компоненты переключают только отображение. Подтверждённый опыт не означает подтверждённую оплату. Черновик отклика и открытое подтверждение выбора сохраняются при RU/KK. [Объём и проверки](qa/f06d-public-marketplace-2026-10-28.md).

Исторически после F06e оставались системные страницы, шаблоны, письма авторизации и внутренние уведомления; они впоследствии получили RU/KK в указанных пределах. Остаются серверные ошибки, редакторская проверка терминов и юридических текстов, native zoom200%, реальные устройства/диктор/Firefox/Safari и измеренная производительность. Готовность F06 целиком этим документом не подтверждается.

### F06e: административные экраны

Девять вкладок администратора, редакторы материалов/лидов, фоновые задания и показатели пилота используют общий выбор RU/KK. Переключение сохраняет фильтры, несохранённые поля, выбранную редакцию, действие и причины решения без повторной отправки. Числа результата Threads хранятся отдельно от отображаемого сообщения. Исходный контент и неизвестные технические детали остаются в оригинале. Права, API, значения статусов и формулы не менялись. [Приёмка и ограничения](qa/f06e-admin-2026-10-28.md). Далее — системные тексты и общая приёмка F06.

### F06f1: помощь и системные страницы

Help, условия, конфиденциальность, 404 и экран ошибки используют текущую локаль. SSR с cookie проверен без JavaScript. Retry не вызывается при смене языка, внутренние сведения ошибки скрыты. Юридические тексты сохраняют статус рабочей редакции пилота. [Проверки](qa/f06f1-system-pages-2026-10-28.md). Далее — метаданные, шаблоны и сообщения/уведомления/письма.

### Быстрый пакет: общие metadata

Root generateMetadata читает cookie только текущего запроса. RU остаётся fallback; название продукта и иконка сохранены. Проверка без JavaScript покрывает KK title/description и возврат к RU при неизвестной cookie. Мгновенное обновление metadata при переключении уже открытой вкладки остаётся отдельно.

Проверки быстрого пакета28.10: production build, typecheck, targeted ESLint, один расширенный SSR E2E и git diff --check успешны. Общий набор56 E2E относится к F06f1 до изменения metadata; повторно не запускался. Локальный сайт после сборки запущен отдельным web-процессом; главная и помощь вернули HTTP200. Фоновые workers этим запуском не поднимаются.

### Письма авторизации RU/KK

Better Auth передаёт исходный Request в обработчики восстановления и подтверждения. Язык письма читается из `qosyl-locale` конкретного запроса, без глобального состояния; если cookie отсутствует, недоступна или содержит неподдерживаемое значение, используется RU. Это язык инициатора запроса, а не сохранённая настройка владельца аккаунта. Фоновые уведомления и пользовательские данные не переводятся этим механизмом. Ссылки, адресат, срок действия и способ доставки не меняются. Редактура носителем языка и реальная SMTP-доставка остаются отдельными проверками. [Проверки](qa/f06-auth-mail-2026-10-28.md).

### Язык получателя уведомлений

В разделе уведомлений кабинета пользователь явно сохраняет язык новых сообщений своего аккаунта; исходное значение — RU. Настройка действует независимо от языка интерфейса на всех устройствах. Новые уведомления рабочих процессов, модерации, сроков и сохранённых поисков создаются на языке получателя. Данные, добавленные участниками, не переводятся; неизвестная формулировка остаётся исходной. Переключение не изменяет старые записи, сроки, адреса или состояние прочтения. [Решение](../11_Reports/Decisions/ADR-014-notification-recipient-language.md).
