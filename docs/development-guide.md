# Qosyl

Техническое руководство. Команды и пути к коду ниже отсчитываются от корня Qosyl. Производственный пакет `package-pilot.ps1` содержит техническую часть, а не полный исследовательский архив.

Рабочий MVP студенческих микропроектов для локального пилота Idea Battle. Заказчик публикует ограниченное задание с бюджетом, модератор проверяет его, студент откликается, стороны согласуют условия, передают результат и подтверждают опыт.

Актуальные определение продукта, аудит и этапы развития: [обзор Qosyl](../README.md). На 25.10.2026 последний предоставленный опрос содержит **45 ответов**: 41/45 оценили интерес на 4–5, 35/45 выбрали гарантию оплаты, 28/45 — чёткое ТЗ, 26/45 готовы выделять менее трёх или 3–5 часов в неделю. Это смешанная нерепрезентативная выборка, не подтверждение спроса бизнеса или фактических сделок. [Методика и сверка предыдущих срезов](../02_Research/Analysis/survey_analysis.md). Полученное ТЗ v2 сохранено как исторический документ со срезом 42 ответа.

Платежи проходят **вне платформы**. Площадка не хранит деньги и не гарантирует оплату. ДЕМО-заказы, профили и действия отделены флагом в базе. Oxford Team — закрытый демонстрационный пример гипотезы; отклики выключены, партнерство не подтверждено.

## Стек

Next.js App Router / React / TypeScript strict, PostgreSQL, Prisma, Better Auth, Zod, Tailwind CSS, Lucide. Тесты: Vitest + Playwright. Адаптивный интерфейс на русском; время — Asia/Qyzylorda, валюта — KZT. Название меняется в `src/lib/config.ts`.

## Быстрый локальный запуск (Windows)

**Текущий план: локальная демонстрация, облачный сервер после финансирования.** На уже подготовленном компьютере открыть `START_DEMO.cmd` или выполнить `npm run demo`. Инструкция, резервирование и ограничения — в [docs/local-demo.md](local-demo.md).

Требуются Node.js 24 LTS, npm и PostgreSQL 18 (бинарные файлы `initdb`, `pg_ctl`, `psql`, `createdb`). Стандартный путь: `C:/Program Files/PostgreSQL/18/bin`, другой задается переменной `POSTGRES_BIN`.

```powershell
npm ci
npm run setup
npm run dev
```

Откройте http://localhost:3000. `setup` создает изолированный кластер в `.local/postgres` на **127.0.0.1:55432**, генерирует секреты в `.env`, применяет миграции и добавляет демонстрационные данные. Системную PostgreSQL-службу и ее данные команда не изменяет. Повторный seed не перезаписывает существующие заказы и пароли. Для остановки отдельной БД: `npm run db:stop`; файлы сохраняются.

Локальные демонстрационные аккаунты и сгенерированный пароль:

```powershell
Get-Content .local/demo-accounts.json
```

Четыре аккаунта: студент, новичок, заказчик и модератор. Seed допускается только при `LOCAL_DEV_MODE=true`, `DEMO_ENABLED=true` и локальной базе. Новые реальные аккаунты регистрируются через интерфейс. Администратор назначается серверной командой `npm run admin -- ...` (инструкции выводятся без аргументов), никогда через регистрацию.

## Другая PostgreSQL / Docker

Создайте `.env` из `.env.example`, задайте уникальные `DATABASE_URL` и `BETTER_AUTH_SECRET`. Для Docker задайте `POSTGRES_PASSWORD` и запустите `docker compose up -d db`. Пароль в URL должен совпадать. Затем:

```powershell
npx prisma generate
npm run db:migrate
npm run db:seed
npm run dev
```

Не запускайте `db:local` для внешней БД; этот helper намеренно ограничен собственной локальной базой.

## Проверки и локальная production-сборка

```powershell
npm run typecheck
npm run lint
npm test
npm run build
npm run start
```

Для Playwright нужен Chromium: `npx playwright install chromium`. После сборки `npm run test:e2e` готовит **отдельную** базу `student_marketplace_e2e`, запускает сервер на localhost:3100 и проверяет полный путь. Эта база не используется пользовательской демонстрацией. Скриншоты и отчеты — `test-results/`, `playwright-report/`.

Проверенные результаты, их дата и ограничения записываются в `docs/qa-report.md`. Наличие команды в README не означает, что она уже успешно выполнена.

## Почта, безопасность и конфигурация

В локальном режиме письма восстановления сохраняются только в `.local/mail`. Прочитать последние письма: `npm run mail`. Ссылки содержат одноразовые секреты — не публикуйте каталог `.local` и не добавляйте его в Git. Локальные регистрации требуют явного согласия с правилами обработки данных и подтверждения возраста18+; email-проверка допускается упрощенной только на loopback.

Публичный запуск требует `LOCAL_DEV_MODE=false`, `DEMO_ENABLED=false`, HTTPS, случайного `BETTER_AUTH_SECRET` и SMTP: `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`. Подтверждение email тогда обязательно. `npm run start` проверяет конфигурацию. Стандартная команда привязана к127.0.0.1; для размещения за защищенным reverse proxy настройте сервис отдельно. Не публикуйте dev-сервер через туннель.

Рабочие права проверяются сервером при каждой операции. Основные изменения и аудит атомарны в сериализуемых транзакциях. Для mutations нужен точный `Origin` сайта и JSON. История событий и содержимое версий соглашения защищаются также миграцией PostgreSQL. Безопасность не сводится к скрытым кнопкам.

`.env`, `.local`, зависимости, сборки и тестовые артефакты исключены из Git. Для переноса/резервного копирования используйте `pg_dump` целевой базы и отдельное защищенное хранение конфигурации; не копируйте работающий каталог PostgreSQL как резервную копию.

- `docs/qa/local-demo.md` — актуальная сверка с ТЗ и результаты локального запуска/восстановления.

- `docs/TZ_Codex_Student_Marketplace_MVP_v2.md` — полная копия полученного ТЗ.

P0 использует HTTPS-ссылки вместо загрузки бинарных файлов. Двустороннее согласие требуется для публикации подготовленного портфолио; приватные ссылки сдачи не копируются туда автоматически. Правки по объему оформляются новой версией условий. Споры требуют ручного рассмотрения, платежного арбитража нет.

Это **локальный MVP для демонстрации**, не заявление о production-ready. Перед публичным пилотом нужны проверка правовых текстов и обработки данных в Казахстане, назначенный оператор/канал поддержки, мониторинг, резервное копирование с проверкой восстановления, проверенный SMTP и отдельная эксплуатационная проверка. Несовершеннолетние и высокорисковые услуги не допускаются. Исследовательские материалы в `research/` и исходный `опросник.pdf` сохранены отдельно от прикладных данных.
