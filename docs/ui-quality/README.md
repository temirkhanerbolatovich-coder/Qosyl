## F06b: перевод авторизации и профилей

Проверки смены языка должны учитывать уже видимые pending/error/success и сохранность несохранённых полей/согласий. `tests/e2e/auth-locale.spec.ts` разделяет реальные записи в изолированную БД и синтетические сетевые ответы. Перед axe после смены темы ожидается завершение конечных переходов: промежуточный цвет не является устойчивым состоянием интерфейса. После навигации проверка состояний также ожидает непустой document title; если он не появляется в пределах timeout, тест завершается ошибкой. [Объём и свидетельства](../qa/f06b-auth-profile-2026-10-27.md).

## F06c: кабинеты и рабочая область

Смена языка проверяется с заполненными формами, выбранным файлом и вложением, а также во время pending и после ошибок. Перед проверкой результата команды тест ожидает её видимый успех: завершение click ещё не означает завершение POST. Приёмка: 44/44 E2E, 196/196 строгих UI-проверок; дополнительно 17 состояний F06c с axe/overflow и выборочным просмотром снимков. [Объём, ограничения и результаты](../qa/f06c-marketplace-2026-10-27.md).

## F06d: публичные карточки и портфолио

Для серверных страниц текстовые клиентские компоненты позволяют менять язык без переноса запросов и приватных моделей в браузер. При проверке портфолио отдельно подтверждать обе стороны согласия и отсутствие private/redacted ссылок; локализация не является правом публикации. Проверять порядок слов у динамических чисел (например, ограничение часов в неделю), а не переводить отдельные предлоги вне контекста. [Сценарии и результаты](../qa/f06d-public-marketplace-2026-10-28.md).

## Запуск проверок

Из корня `Qosyl/`, при готовой production-сборке и локальном PostgreSQL:

```powershell
npm run ui:tokens
npm run test:ui:baseline
npm run test:ui
npx playwright show-report .local/ui-quality/baseline/report
```

Baseline — сбор исходных наблюдений, строгий запуск — проверка серьёзных/критических axe-ошибок и overflow. Оба запускают порт 3100 и отдельную БД `student_marketplace_e2e_ui_<суффикс>`, не используют основную БД и отключают Threads в тестовом сервере. E2E_BASE_URL/E2E_EXTERNAL_SERVER для этого runner запрещены. Результаты находятся в `.local/ui-quality/`, защищены от случайного коммита через существующий `.gitignore`; JSON-сводка без cookies — в `outputs/ui-quality/`.

Открывать репозиторий как проект рекомендуется из `Qosyl/`. [Официальное руководство](https://learn.chatgpt.com/docs/build-skills) описывает поиск `.agents/skills` от текущего каталога к корню; родительский каталог текущего чата содержит дополнительный AGENTS-указатель. Проверка установленного Codex CLI через app-server `skills/list` реально обнаружила `ui-quality`, enabled=true, scope=repo: [свидетельство](../../outputs/ui-quality/skill-discovery.json). Факт появления в селекторе Desktop отдельно не подтверждён. Файл можно явно загрузить по пути даже до обновления селектора.

Счётчики результата хранить как числа, переводить при показе, сохраняя стабильные API-коды. Просмотр workers не должен запускать команды.
