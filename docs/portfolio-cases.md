# Самостоятельные кейсы портфолио

29.10.2026. В `/student/profile` доступны вкладки «Профиль» и «Портфолио». Переключение не размонтирует формы и не отправляет команды. Резюме и советы остаются следующими этапами; пустых вкладок для них нет.

## Пользовательский сценарий

Исполнитель добавляет кейс: название, роль, описание, проблема, личный вклад, год/период, инструменты, результат, основная и до пяти дополнительных HTTPS-ссылок. Ссылка необязательна. Новая форма начинает с draft. Можно сохранить черновик, приватный кейс или явно разрешить публичную публикацию. Публикация требует подтверждения права раскрывать описание и материалы; пользователь может подготовить обезличенный текст. Частные вложения проекта нельзя указать как публичные материалы.

Кейсы помечены «Добавлено пользователем · self_reported». Список поддерживает редактирование, удаление с подтверждением, перемещение выше/ниже и предпросмотр сохранённых публичных кейсов. Порядок сохраняется и используется на публичной странице. Публичный профиль по-прежнему необходим для гостевого доступа. Новый черновик и private никогда не попадают в гостевой HTML и список работ в API откликов заказчика.

Подтверждённые проекты показываются отдельной группой «Выполнено на Qosyl · platform_verified». Проверяются связь PortfolioRecord.studentId с текущим назначенным исполнителем, accepted/completed и серверное событие acceptSubmission. Публичный вывод дополнительно требует обоих прежних согласий и публичной видимости записи. На вкладке владельца есть ссылки в рабочую область для согласования. Редактор самостоятельных кейсов не изменяет PortfolioRecord, статусы проектов, отзывы, оплату и проектные согласия. Подтверждение результата не подтверждает фактическую оплату.

## Хранение и совместимость

Расширена существующая ExternalPortfolioItem: устойчивый id, поля кейса, visibility, publicationAllowed, position, revision. Таблица не заменяется, старые строки не удаляются. Миграция 20261029060000_portfolio_cases сохраняет прежние title/description/url/createdAt/id, устанавливает прежним работам public + разрешение (раньше они публиковались вместе с профилем), восстанавливает прежний порядок createdAt DESC с id как разрешением одинаковых дат. Новые записи по SQL default — draft без разрешения. Прежний закрытый профиль остаётся закрытым. Старое разрешение перенесено как совместимость, а не новая юридическая проверка прав автора.

Обычное сохранение профиля больше не отправляет externalWorks и не удаляет/создаёт их заново. Старый POST /api/profile с неизменным набором трёх прежних полей работает как no-op для кейсов; попытка заменить существующий набор даёт 409 и откатывает всю транзакцию. Первоначальный legacy импорт разрешён только в пустой список и создаёт черновики. Для редактирования и публикации требуется новый endpoint. Это намеренная защита от потери ID, новых полей и приватности устаревшим клиентом.

## API и защита

GET /api/profile/portfolio возвращает только собственные кейсы в порядке показа. POST принимает строгий discriminated union action=create/update/delete/reorder. create и update содержат data; update/delete требуют id и revision. reorder принимает полный текущий набор {id,revision} в нужном порядке. Частичный, чужой, повторяющийся или устаревший набор отклоняется. UUID revision обновляется при изменении и перестановке; устаревший редактор получает 409 вместо потери чужого изменения. При конфликте текст остаётся в форме; обновление списка не перезаписывает его, для работы с новой версией нужно открыть её заново после сохранения нужного текста.

Границы: session, same-origin, student role, active account, demo flag и подтверждённый email вне localMode; повторная проверка в транзакции. Блокировка строки владельца сериализует изменение, квоту и reorder. Максимум 30 кейсов, тело JSON 32 КиБ, до 40 успешно завершённых команд в минуту. Невалидная команда не пишет изменения; лимит успешных команд не является защитой от распределённого DDoS. В аудит пишется тип действия без содержимого кейса. Неизвестные поля userId/projectId/source/consent отклоняются; проверенное происхождение нельзя присвоить самостоятельному кейсу.

Ссылки переиспользуют HTTPS-проверку профиля и запрет путей /api/attachments. Сервер не загружает внешние страницы. React экранирует пользовательские тексты. Для произвольного внешнего домена нельзя доказать отсутствие секретов по URL: автор отвечает за право публикации; нет проверки содержимого внешнего ресурса или DNS.

## Откат и ограничения

Перед миграцией — проверенный backup/restore, затем db:migrate без reset/seed. Откат старого кода опасен: старый код публикует все внешние работы и удаляет/пересоздаёт их при сохранении профиля. Сначала экспортировать новые поля, порядок и приватность, сохранить фильтр публичности и запрет разрушительного bulk-save в откатываемой версии. Не удалять колонки до сохранения данных и решения доступа. Общая старая резервная копия не должна перезаписывать новые пользовательские данные.

Порядок меняется внутри самостоятельных кейсов. Подтверждённые проекты остаются отдельной группой по времени создания; объединённая ручная сортировка двух источников не добавлена. Изображения кейсов не загружаются: безопасный аватар имеет другое владение и жизненный цикл, его нельзя использовать как галерею кейса. Нет PDF, отдельной публичной страницы кейса, автоматической проверки прав или импорта изображений. Вкладки резюме/советов — будущие этапы. Полный ответ для массового набора тестов ограничен общим auth rate-limit: запускать регистрационные группы изолированно. Изменения локальные, без внешнего развёртывания.
