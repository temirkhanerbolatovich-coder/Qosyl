# Запуск фоновой актуальности Q11

`npm start` запускает `scripts/run-platform.mjs`: после проверки окружения supervisor владеет веб-сервером и отдельным worker. Неожиданное завершение любого дочернего процесса останавливает второй и возвращает ошибку; частично работающая платформа не остаётся незамеченной. `npm run demo` после прежних setup/build использует тот же запуск. База при остановке не удаляется.

Worker можно запускать отдельно из корня Qosyl:

```powershell
node --conditions=react-server --import tsx scripts/project-lifecycle-worker.ts --once
node --conditions=react-server --import tsx scripts/project-lifecycle-worker.ts
```

Первый вариант выполняет один проход и завершает процесс, второй повторяет проходы. Вызовы ожидаются последовательно; новый проход не начинается поверх предыдущего. Флаг `--conditions=react-server` разрешает серверные маркеры импортируемого кода. Остальные флаги, включая изменение времени через CLI, не принимаются.

| Настройка                     | По умолчанию | Допустимо            |
| ----------------------------- | ------------ | -------------------- |
| PROJECT_LIFECYCLE_ENABLED     | true         | true / false         |
| PROJECT_LIFECYCLE_INTERVAL_MS | 60000        | целое 1000..86400000 |
| PROJECT_LIFECYCLE_BATCH_SIZE  | 50           | целое 1..50          |

Выключенный worker завершает процесс до импорта модулей БД и не выполняет проходов. Supervisor при выключении продолжает запускать веб-сервер. Неверная конфигурация останавливает запуск. После ошибки БД непрерывный worker повторяет проход с паузой от секунды до минуты; `--once` возвращает ненулевой код. Сырые исключения, URL подключения и пользовательские данные не выводятся в лог CLI; пишутся только статус и счётчики.

Ctrl+C / SIGTERM запрещает новые проходы, пробуждает ожидание и позволяет текущей транзакции завершиться. Supervisor завершает дочерние процессы и ограничивает ожидание 20 секундами. На Windows прекращение дочернего Node может быть немедленным; PostgreSQL откатит незавершённую транзакцию и освободит её блокировку. Оба дочерних процесса контролируют существование supervisor: даже после принудительного Stop-Process родителя завершаются примерно за секунду и не остаются самостоятельными сервисами. После перезапуска постоянные ключи уведомлений защищают от повторной отправки.

Образ Docker запускает тот же supervisor с адресом 0.0.0.0:3000. Отдельная Compose-служба worker не требуется. Команда миграции остаётся отдельной подготовкой; worker и веб должны запускаться после её успеха. Для выключенного компьютера или контейнера непрерывная актуализация не обещается: после запуска выполняется следующий проход.

Тесты runtime проверяют выключение без БД, параметры, отсутствие перекрытия проходов, остановку, безопасные ошибки и реальное завершение дочернего процесса вместе с его соседом. Production Docker и внешнее развёртывание этим локальным тестом не подтверждаются.
