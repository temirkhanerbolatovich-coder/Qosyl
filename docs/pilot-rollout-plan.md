# Поэтапное продолжение после локального MVP

Основание: пользователь одобрил постепенное выполнение следующего плана 25.10.2026. Исходные исследования и ТЗ сохраняются. Уже подготовленные файлы MVP не сбрасываются и не заменяются шаблоном.

**Актуальное решение владельца25.10.2026:** сначала полный локальный MVP и демонстрация на компьютере; покупка сервера после финансирования. Ниже сохранен план будущего внешнего пилота, он больше не блокирует локальную готовность. Ближайшие действия: сверка P0 с ТЗ, удобный локальный запуск, проверенный backup/restore, регрессия и репетиция. См. `local-demo.md`. Попытки создавать облачные ресурсы и настройка Oracle Email Delivery/DuckDNS отложены, платный тариф не включается.

| Шаг                 | Результат этапа                                                                                              | Как подтверждаем                                                      | Текущий статус                                                     |
| ------------------- | ------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------- | ------------------------------------------------------------------ |

| 3. Размещение       | HTTPS, секреты, отдельная production-БД, отключенное demo, закрытая первоначальная аудитория                 | Проверка конфигурации и smoke после размещения                        | После почты и выбора среды                                         |
| 4. Эксплуатация     | Backup/restore, наблюдаемость, минимальные DB-права                                                          | Действительное восстановление в отдельную БД и проверки отказов       | Следующий технический этап                                         |

Каждый этап завершается документированными проверками. Наличие переменных SMTP не означает доставку, успешная локальная проверка не означает готовность публичного пилота, демо не считается реальным заказом.

## Обновление25.10.2026

Шаг1: исправлены3дефекта уведомлений/статусов, текущие20unit и14E2E проходят, production build проходит. См. `qa/pilot-step-1.md`.

Шаг2: реализованы строгие TLS-настройки SMTP и `npm run mail:check` (конфигурация, опционально connect/login без письма). Реальный провайдер и доставка остаются неподключенными.

Владелец выбрал Oracle Email Delivery; настройка после появления новой VM. DuckDNS остается адресом сайта и не используется как почтовый домен отправителя.

Шаг3: владелец выбрал Oracle Cloud, новую VM и DuckDNS; кандидат `student-project-kz.duckdns.org`. Подготовлены Dockerfile, production Compose, proxy, DNS-updater, разделение DB-ролей и healthcheck. Проверена синтаксическая конфигурация Compose; image build/run на Linux еще впереди.

После обнаружения лимита2VCN владелец уточнил: при достаточной квоте ничего старого не удалять. Подготовленное удаление SAQ отменено. Работающий TimScheduleBot сохранен; перенести разрешено лишь при реальной необходимости и с проверкой работы. Новая VM готовится в существующей VCN с отдельной подсетью.

Попытка Create новой Always Free A1 (1OCPU/6ГБ) после подтверждения владельца и один ограниченный повтор: Oracle вернул `Out of capacity` в Tokyo AD-1. VM не создана, IP нет, отдельная подсеть тоже не создалась; старые VM и диски не удалялись. Платный тариф и постоянные автоматические повторы не включались.
