# Threads: подключение поиска Q24

**Актуальное ограничение доступа.** Причина пустой выдачи установлена 26.10.2026 по официальной документации Meta: без одобрения `threads_keyword_search` поиск ограничен публикациями авторизованного пользователя. `GET /me/threads` под `gruppavtipo252` вернул HTTP 200 и `data: []`; исходный `/keyword_search` также вернул пустой массив до нормализации Qosyl. Панель Meta показывает «Готово к тестированию», а попытка добавить разрешение в App Review требует необратимого статуса Tech Provider, подтверждения компании и прав доступа. Переход не выполнен, заявка не отправлена. Владелец отказался от создания тестового поста и выбрал поиск чужих публикаций через App Review. Получение чужой публикации пока заблокировано одобрением Meta.

Владелец выбрал официальный Threads API 26.10.2026. Реализован **поиск по запросу admin с предварительным просмотром**: публикация → пустая форма кандидата → явное сохранение Lead → прежняя ручная проверка. Пост не становится заказом. 26.10.2026 приложение Qosyl авторизовано через OAuth под `gruppavtipo252` с `threads_basic,threads_keyword_search`. Профиль и keyword_search вернули HTTP 200; долгосрочный токен сохранён в локальном `.env`, поиск включён, общий supervisor перезапущен. Запросы «нужен сайт» и «Threads» дали пустую выдачу: получение известной публичной публикации и охват ещё не подтверждены.

## Как получить доступ

1. Откройте [Meta for Developers](https://developers.facebook.com/) под своим аккаунтом и создайте приложение с вариантом использования **Threads**. Подключите свой Threads-аккаунт согласно требованиям панели. Для режима разработки настройте доступ владельца/тестировщика и примите требуемые приглашения.
2. В настройках Threads приложения проверьте доступность `threads_basic` и `threads_keyword_search`. Эти имена присутствуют в [официальной коллекции Meta](https://github.com/fbsamples/threads_api/blob/main/postman/threads-api.postman_collection.json). Для Qosyl не нужны разрешения публикации, ответов или удаления. Наличие scope в токене само по себе не доказывает доступ приложения к поиску по нужным публичным постам: проверьте уровень доступа/требования Review в текущей панели Meta. Не обещаем обход Review, конкретные квоты или бесплатный неограниченный поиск.
3. Получите **пользовательский Threads access token**, а не App Access Token. Если текущая панель предоставляет генератор пользовательского токена, используйте его для своего тестового аккаунта. Иначе используйте OAuth 2.0 Authorization Code из [официальной коллекции Meta](https://www.postman.com/meta/threads/collection/dht3nzz/threads-api): Threads App ID/Secret, запрошенные scopes, согласие пользователя, обмен code на токен. Threads App ID/Secret отличаются от обычных ID/Secret приложения — это отдельно отмечено в [официальном sample app](https://github.com/fbsamples/threads_api).
4. Redirect URI должен точно совпадать при авторизации и обмене code. Для локального OAuth официальный sample требует HTTPS и локальное имя домена вместо localhost. Qosyl на http://localhost:3000 не является готовым OAuth callback; новый callback в этот выпуск не добавлен. При необходимости следуйте setup официального sample app в отдельной папке или используйте доступный инструмент панели. Не меняйте публичный режим Qosyl ради получения токена.
5. Проверьте тип, scopes и срок токена через официальный инструмент Meta. После выдачи доступа выполните read-only поиск по известному разрешённому публичному примеру: проверьте, что возвращается ожидаемый пост, а не только пустая/ограниченная выдача. Нулевой результат не доказывает отсутствие спроса. Реальные данные не публикуйте автоматически.

OAuth URL/обмен и refresh показаны в [официальной документации коллекции](https://www.postman.com/meta/threads/documentation/dht3nzz/threads-api). Клиент Qosyl не получает и не обновляет токен самостоятельно; по истечении срока владелец заменяет его и перезапускает приложение. Не отправляйте токен, App Secret или полный URL запроса в чат/логи/скриншоты.

Страницы Meta Developers при исследовании отвечали 429. Контракт GET `/keyword_search`, параметры `q`, `search_type=RECENT`, `limit`, `fields` и ответ `data` проверены по JSON официального репозитория fbsamples/threads_api. Orbit нашёл соответствующий ресурс, но `/integrate` дважды вернул 404; это не считается успешной проверкой Orbit integrate. Числовые квоты и итоговый публичный охват API не установлены.

## Особенность генератора токенов Meta

В этой настройке генератор панели выдавал действительный токен без `threads_keyword_search`, хотя разрешение приложения имело статус «Готово к тестированию». Профиль возвращал 200, поиск — 403/код 10. Повторная генерация это не исправила. OAuth Authorization Code с явным scope `threads_basic,threads_keyword_search` через официальный Postman OAuth helper дал доступ к поиску (200). В Meta зарегистрирован redirect `https://oauth.pstmn.io/v1/browser-callback`; используются Threads App ID/Secret, отправка client credentials в теле. Токен в Postman не включён для общего использования. Секреты, коды и токены не помещать в документацию или экспорт коллекции. Долгосрочный токен получен официальным обменом; автоматического обновления в Qosyl нет.

## Локальная настройка

В существующем `.env` Qosyl задайте значения самостоятельно:

```dotenv
THREADS_SEARCH_ENABLED=false
THREADS_ACCESS_TOKEN=
```

Впишите действующий пользовательский токен только в `.env`. После подтверждения доступа измените `THREADS_SEARCH_ENABLED=true` и перезапустите существующий supervisor (`npm start`). Если порт 3000 уже занят прежним экземпляром, сначала штатно остановите его. Повторная миграция, seed и пересоздание БД не нужны. `.env` исключён из Git; `NEXT_PUBLIC_*` для токена запрещён.

Откройте admin → «Лиды и обсуждения» → «Поиск в Threads», введите тему и нажмите «Найти публикации». Оригинал открывается отдельно. «Заполнить пустую форму кандидата» заполняет ссылку, источник, название и суть; непустая форма защищена от перезаписи. Проверьте текст, выберите тип/ответственного/срок и явно сохраните. Дата поста — не срок актуальности или согласие. Исходная публикация и её автор не становятся аккаунтом заказчика.

Повтор ссылки того же типа возвращает прежний Lead без обновления/возрождения. Поиск ничего не перезаписывает в проверенной записи, не добавляет автоматических редакций и не фиксирует согласие. Обновления исходного поста оператор рассматривает вручную. Идентичность существующего реестра — тип + канонический URL; глобальная идентичность по ID Threads при переименовании автора пока не гарантируется.

## API и отказ

- `GET /api/admin/leads/threads`: свежая активная роль admin; только `enabled` и `configured`. Это локальная готовность, не доказательство доступа Meta. Внешнего запроса нет.
- `POST` того же пути: сессия admin, точный same-origin Origin, JSON до 2048 байт, строго `{ "query": "нужна таблица" }`, 2–100 символов после trim.
- Один GET к фиксированному `https://graph.threads.net/keyword_search`, RECENT, limit 25, только id/text/permalink/timestamp/username. Нет paging, redirects, файлов/медиа или автоматических повторов. Timeout 10 секунд, тело ответа до 256 KiB. Ссылки допускаются только HTTPS Threads `/@name/post/code`; .net/.com приводятся к www.threads.com, tracking удаляется. Невалидные/слишком короткие посты отбрасываются; повтор ID/URL в выдаче исключается.
- Локальные технические потолки: 5 попыток за минутное окно на admin и 100 за общее 24-часовое окно от первого запроса. Это ограничения Qosyl, а не опубликованные квоты Meta. Попытка учитывается до внешнего вызова, включая неуспех; счётчики сохраняются в существующей RateLimit. Общий lock БД удерживается только при проверке счётчиков, не во время сети.
- Provider 429/Graph throttling устанавливает общую паузу: Retry-After 1–86400 секунд, при отсутствии/невалидном значении — 60 секунд. До её окончания новые вызовы не отправляются. Локальный ответ 429 сообщает о паузе; автоматического retry нет.
- 503: выключение/отсутствие токена, отказ доступа, timeout/5xx/неподдерживаемый ответ. Свежая роль и выключатель повторно проверяются перед возвратом результата. Уже начатый запрос может завершиться, но при выключении результат не выдаётся. Переключатель окружения применяется перезапуском процесса.
- 401/403: вход/права/origin; 400/413/415: входные данные. Все ответы private/no-store. Ошибка или выключение не блокируют ручной реестр и биржу. Полные upstream-ошибки/URL/токены не логируются и не возвращаются.

## Границы и проверки

Это первый адаптер с ручным запуском поиска, без фонового мониторинга, гарантии полного покрытия, сохранённого cursor, Inbox-таблицы, автоматического импорта или OAuth UI. Выдача временная, сохраняется только явно выбранный человеком Lead. Новых зависимостей и миграций нет. Решение: [ADR-007](../11_Reports/Decisions/ADR-007-threads-search-preview.md).

Проверки: `npm test` (включая настоящий клиент с локальной HTTP-fixture), `npm run test:leads` (PostgreSQL + HTTP), `npm run test:e2e`, build/lint/typecheck/api:check. Postman CLI недоступен: нативная HTTP-fixture не называется Postman simulation. В E2E preview имитируется только на уровне браузера; серверные границы/выключение проверяются настоящими HTTP-запросами, а outbound клиент — отдельно. [Фактическая приёмка](qa/threads-search.md).
