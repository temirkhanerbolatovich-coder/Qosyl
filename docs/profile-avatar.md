# Безопасный аватар профиля

29.10.2026. В `/student/profile` исполнитель может загрузить, заменить, отдельно разрешить публикацию и удалить фотографию. Действия сохраняются сразу, независимо от кнопки сохранения остальных полей. Ошибка не удаляет предыдущий аватар. При отсутствии или недоступности изображения показывается инициал. Есть RU/KK тексты, клавиатурный доступ и состояние выполнения.

## Обработка и доступ

POST `/api/profile/avatar` принимает тело JPEG/PNG, не multipart. Максимум 2 МиБ и 16 миллионов пикселей; проверяются объявленный размер, фактический поток, MIME, сигнатура и декодирование. SVG/GIF/WebP и анимация не поддерживаются. Sharp декодирует пиксели, применяет ориентацию, уменьшает до 512×512 без увеличения, сводит прозрачность на белый фон и заново кодирует JPEG. EXIF/ICC/XMP, имя файла и исходные байты не сохраняются. Выход ограничен 512 КиБ. Чтение потока ограничено 20 секундами, обработка пикселей — 5 секундами.

GET `/api/profile/avatar` возвращает только собственные метаданные. PATCH принимает `{revision,isPublic}`, DELETE — `{revision}`; строгие схемы отвергают дополнительные ключи. Устаревшая версия даёт 409. POST создаёт новую версию с isPublic=false даже при замене опубликованной фотографии. Все изменения требуют своей активной сессии исполнителя, same-origin и подтверждённой почты вне localMode. Попытки, включая неправильные файлы, учитываются до чтения и декодирования: 10 в минуту на аккаунт. Состояние аккаунта проверяется повторно в транзакции перед записью. Изменения журналируются без содержимого фотографии.

GET `/api/avatars/{userId}` отдаёт JPEG владельцу либо посетителю при одновременных isPublic аватара и профиля. Блокировка аккаунта закрывает чтение; отдельного обхода для администратора нет. Ответ содержит private/no-store, nosniff, same-origin CORP и CSP sandbox. Next image optimizer не используется, чтобы не создавать публичный кеш приватных байтов. URL не является разрешением доступа: права проверяются при каждом запросе.

## Хранение и сопровождение

Таблица ProfileAvatar хранит максимум одну перекодированную фотографию на User, UUID revision и отдельное согласие. Двоичные данные не включаются в общие profile/marketplace JSON. SQL CHECK ограничивает размер. Миграция 20261029050000_profile_avatar аддитивная и не меняет существующие профили, проекты, вложения или Google User.image. Переиспользован потоковый reader приватных вложений с параметром размера; правила доступа самих вложений сохранены.

Sharp 0.35.5 уже присутствовал через Next, теперь закреплён прямой зависимостью: сервер непосредственно вызывает его API. Основания: [ограничения входа](https://sharp.pixelplumbing.com/api-constructor/) и [перекодирование с удалением метаданных по умолчанию](https://sharp.pixelplumbing.com/api-output/). Совместимость проверена сборкой и обработкой реальных JPEG/PNG. Обновления декодера требуют повторения негативных тестов.

До применения миграции выполнить `npm run db:backup -- --verify`, затем `npm run db:migrate`. Откат кода может оставить новую таблицу. Удалять таблицу допустимо только после сохранения/экспорта новых фотографий и согласий; не восстанавливать всю старую БД поверх новых пользовательских данных. Замена и удаление убирают живую запись/байты; старые резервные копии подчиняются отдельной политике хранения.
